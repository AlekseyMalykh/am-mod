# Отделение строк и событий из блока Arrange

Реализовано в той же ветке `codex/pad-midi-recording`, под прежним opt-in
Pattern Tools. Это развитие существующего Piano Roll, а не новый редактор.
Формат штатных Sequence и optional AMP1/AAR1 в XPJ не изменён. Новая сборка
на карту в рамках этого этапа не устанавливалась.

## Короткий рабочий путь

В обычном Song **Shift+B1 открывает Arrange** без Export chooser.
Транспорт должен быть остановлен и clock context доступен. На временной
шкале Arrange Shift+B1 возвращает Sequential Song; применённые операции
сохраняются, незавершённый preview отменяется. B1 без Shift остаётся Export
в обычном Song и Back/Cancel в Arrange. В Piano Roll Shift+B1 сохраняет
прежний выбор Cursor/Notes; для выхода из него нужен B1 Arrange.
Сочетание переопределено только при включённом trial-флаге, не в baseline.
Подпись Shift+B1 на Song меняется на Arrange, в Arrange — на Song.

1. B3 Open на блоке открывает существующий Pattern host с числовым Clip ID.
2. Удерживать B2 и нажимать пэды: каждая строка включается/выключается
   целиком. В Pad view выбираются все события пэда по всей длине Pattern;
   Bank позволяет выбирать строки других банков в том же жесте.
3. Не отпуская B2, нажать **B3 Separate**. Никакое меню для отделения не нужно.
   Редактор закрывается, новая партия выделяется на строке сразу под исходной.
   DATA/B3 Edit/Chop работают с новым блоком обычным способом.
4. Для копирования вместо отделения: отпустить B2 → Shift+B3 Actions →
   Copy selection. Исходный текущий блок в этом случае сохраняется целиком.

Короткое нажатие B2 продолжает включать/заканчивать Range. Если удержание
использовано с пэдами, отпускание не меняет Range. В Tune/Chop выделяются
события конкретной высоты/среза текущего пэда. Например, +4 одного пэда
можно отделить от его остальных высот. Bank листает страницы раскладки;
в pattern Tune исходная страница -12..+3, +4 находится на следующей.
Не назначенные на физический пэд строки игнорируются. Audition не запускается.

Можно выделить отдельные ноты через DATA/область и использовать Separate
selection из того же плоского Actions. Новые действия видны только при входе
из Arrange с контекстом блока. Standalone Pattern/штатный Events не получают
неработающие пункты отделения. Удержание B2+B3 также отделяет уже выделенные
ноты без меню.

## Транзакция

`pt_arr_separate` работает с полным скопированным снимком Pattern, его ID,
Clip ID и runtime receipt Store. Выделенные события получают самостоятельный
Pattern с полной исходной длиной периода, каталогом Route и прежними native
байтами, IDs и provenance. При частичном отделении создаётся также Pattern
остатка, на который переназначается только текущий блок. Остальные ссылки
и исходный Pattern остаются прежними. Copy selection не заменяет исходник.

Выделенный блок сохраняет start/length/offset/clip mute; новая дорожка
наследует mute/solo исходной и вставляется сразу после неё. Если выделены
все события, создаётся самостоятельный Pattern без пустого остатка;
прежний Clip ID переносится на новую строку и ссылается на этот новый Pattern.
Даже в этом случае последующее редактирование не меняет другие экземпляры.
Вся операция — один Undo. Лимиты patterns/events/tracks/clips проверяются
до создания дочерних объектов. При лимите остаётся обычный Move без создания
нового музыкального материала.

Границы блока не сокращают длительность нот и не определяют новую длину
Pattern. Ранние triggers длинного аудио не превращаются в audio seek.
Строки остаются музыкальными партиями; Route mixer_bus — прежняя provenance,
а не назначение отдельной шины для новой музыкальной дорожки.

## Защита и проверки

Store получил монотонный runtime serial: успешные edit/history/reset/load
меняют receipt. Undo/Redo не делают старое выделение снова действительным,
даже если прежние Pattern ID/revision восстановились. Это не native lease.
Редактор проверяет Clip → Pattern и перезагружает скопированные значения
после смены receipt. Полный снимок сверяется с исходными событиями, включая
одинаковые occurrences. Неполные/изменённые снимки и stale receipt отклоняются.

Возврат из editor происходит после завершения его button handler, с кодовым
callback и числовым ID новой партии. Между публикацией Store и закрытием
не перерисовывается устаревший host. Никакие Events/Project/Program/surface
указатели в транзакцию или callback не передаются.

`verify_arrangement_separate.py`: host/ASAN, ARM/UBSan, совпадение multiset
подготовленных музыкальных событий до/после отделения; сохранность других
ссылок, period/offset/repeats/tails и duplicate occurrences; независимое
отделение всех строк; Copy, mute/solo, Undo/Redo, codec roundtrip, stale
receipt и лимиты. Отказы аллокации не меняют Store, receipt и выходной ID.
`verify_pattern_tools.py`: настоящий редактор при невалидных native Events
указателях, B2+Pads, Tune +4, быстрый B3 Separate и Actions, безопасный close,
rebind/reset и O2 production codegen. `verify_arrangement_ui.py`: Shift+B1,
парные release, stop guard и выбор новой партии в Song; editor handoff здесь
фиксирован тестовым receiver, реальный editor проверяется отдельно.

Это не подтверждение аудиовоспроизведения Arrange. Совпадение множества нот
не доказывает неизменный порядок одновременных triggers: при подключении
playback отдельно проверить choke groups и другие эффекты порядка. Record,
native executor/voice ownership, полный GUI/XPJ roundtrip, group Move/Chop,
Merge events и аппаратный тест остаются дальнейшими этапами.
