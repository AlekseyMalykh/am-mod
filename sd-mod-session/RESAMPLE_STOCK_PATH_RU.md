# Штатный экспорт одного обработанного пэда

27.10.2026, ELF1.3.0.12,
SHA256 `b6584cba76e416e432ad202509099d34373dc2c3d6a8fb625f5678bf0193b508`.

Требование пользователя: расширить штатный Resample Seq вторым режимом,
который записывает звучание одного настроенного пэда на выбранную цель.
Отдельная цепочка FX и ручная сборка результата из исходного WAV исключены.

## Что найдено

- `18c62f0` запускает общий экспорт `18c5a00` с режимом2 (Seq).
- `18c63b0` запускает тот же экспорт с режимом3 (один инструмент).
- В режиме3 настройки получают Source4, Project/Program/Track и индекс
  выбранного пэда из Project+500. Экспортёр разрешает инструмент через
  `286bbe0`, рассматривает восемь слоёв (`2803c10`), границы среза и высоту
  при расчёте длительности. Это статический аудит, а не аудиотест.
- `2a02ee0` вызывает выбранный экспортёр через RELRO-слот7167218.
  Соседний слот7167220 относится к другому виду экспорта и не меняется.
- Штатный `153ed50` подготавливает путь, проверяет ресурсы, сохраняет цель
  в своём поле150 и передаёт callback `153f200`. Callback назначает
  полученный штатный Sample через штатную группу Undo и сброс цели.
- `153ed50` ожидает PadsBehaviour по полному ResamplePadMode+48.
  Соответствие подтверждается конструктором, vtable и offset-to-top.

## Код

`src/resample_stock.cc/.h` — адаптер штатного экспортёра. В r19 подключён
к меню через `resample_stock_backend.cc` и `resample_simple_ui.cc`:
Shift+пэд11 → Seq/Sample → выбор цели → подтверждение. Полный рендер и
назначение результата на устройстве ещё требуют проверки.
Устанавливает проверенный указатель только в RAM клона и возвращает RELRO
странице доступ только для чтения. Вызов `resample_stock_start` предназначен
исключительно для владельца модели после проверки проекта и подтверждения
замены. На время синхронной подготовки экспорта thread-local состояние
переключает Seq на режим одного инструмента. Другие вызовы сохраняют Seq.
Исходник, цель, полный Mode и его базовые части проверяются до запуска.

Результат1 означает вызов штатного экспортёра, а не готовый звук или
успешное назначение. Поле150 остаётся нужно асинхронному callback; второе
задание запрещено запускать до завершения первого. Backend отслеживает
срок жизни штатного callback и проверяет результат назначения на владельце модели.
Нельзя подменять такой жизненный цикл таймером или считать возврат из
функции окончанием рендера.

## Проверено локально

`wsl -d Ubuntu -u root -- bash -c 'python3 verify_resample_stock.py'`

Обычная ARM-сборка и UBSan под QEMU выполняют настоящие18c62f0,
18c63b0 и18c5a00:

- ABI с аргументами в регистрах и стеке, частота/разрядность и два флага;
- Source4 и каждый индекс0–127 в настоящих AudioExportSettings;
- RAM-переключение с сохранением соседнего слота;
- адаптер Seq/Sample, неправильный базовый указатель, занятый счётчик,
  неверный/изменившийся источник, неверная цель;
- посторонний экспорт из параллельного потока остаётся Seq.

Границы теста явно перехвачены: `18c54d0` (постановка фонового задания)
и, для отдельного теста адаптера, `153ed50`. В тесте настроек Program пуст,
поэтому ветка расчёта длительности слоёв не выполняется. Полный движок,
назначение, воспроизведение и состав записанной обработки этим не доказаны.
Отчёт: `build/resample-stock/verification.json`. Карта не изменялась.

## Что остаётся

### Результат пробы r19a и изменение r19b

Журнал r19a: два вызова Sample source1 → target0 завершились штатным
назначением. Перед импортом WAV полностью прочитан: PCM24 stereo44100,
195942байта, peak0. Тишина присутствует в самом файле. Source0 вместо
source3 недостаточно, поэтому гипотеза r19a не считается аппаратным решением.

r19b меняет только BL18b9b6c: вызов из одиночного экспортёра перенаправлен
в RAM через ближнюю RX-страницу в адаптер обычного Sample receiver211b090.
Он проверяет взаимное соответствие Program12a8/14a8, меняет MIDI-номер в
копии события на индекс пэда и использует штатную маску7ffffffa. Это тот же
receiver, который уже прошёл аппаратную пробу прослушивания Chop в редакторе.
Длительность, запись WAV, обработка, импорт и Undo остаются штатными.
Нативный Seq-callsite не меняется. Ближняя страница создаётся только через
MAP_FIXED_NOREPLACE; существующие отображения не замещаются, после
записи кодовые страницы RX, данные RELRO снова R. Всё — только в RAM клона.

Локальный тест выполняет настоящий18b9a50 и новый BL через relay, проверяет
MIDI60 → pad18, сохранение остальных байтов события, отказ при неверной
таблице/отсутствующем Program. Конечный receiver и writer в этом тесте
подставлены: исправление звука r19b ещё нужно подтвердить на устройстве.

Пункты привязки меню, владельца, подтверждения цели и времени жизни callback
выполнены в r19. Аппаратная проба r19: Sample назначается, но результат тихий.
В r19a меняется только источник входа отдельной созданной ноты:
`18b9b60 mov w4,#3` → `mov w4,#0`, перед настоящим `211aa30`.
Штатный `282fe30` отклоняет source3 при политике1, а source0 (обычный пэд)
принимает. Это воспроизведено выполнением настоящего `18b9a50`; конечный
сэмплер и запись файла в этом тесте — границы с подставными получателями.
Отдельный путь Seq не меняется. Undo называется Resample для обоих режимов.
Callback уведомляет после возврата штатной функции, без ожидания уничтожения
всех её копий. WAV читается перед импортом для журнала peak/bytes/format.

1. Проверить выходной Sample и воспроизведение, Undo, сохранение и загрузку;
   сравнить применение настроек B1/B2/B3 и назначенного FX на устройстве.
2. По журналу `FILE_AUDIO` отличить тихий файл от проблемы целевого пэда,
   если аппаратный симптом сохранится.

Ручной PCM-путь r18a и исследование отдельного захвата выхода AudioIO не
подключаются к этому маршруту. Причина прежнего SEGV r18a не объявляется
исправленной только на основании перехода к штатному механизму.


### Аппаратная проба r19c и проверочная r19d

r19c на устройстве: EQ слышимо заработал, счётчики показали3490 обработанных
вызовов. Подготовка адаптера прошла; SINGLE_TRIGGER source1/midi37 исполнился.
Однако WAV полностью нулевой: PCM24/stereo44100,195942байта,peak0 до импорта.
Это исключает объяснение «звук есть в WAV, но цель не проигрывается».

r19d заменяет аппаратный маршрутизатор211b090 на211aa30 с явной проверенной
дорожкой CurrentThings+140. Дорожка должна принадлежать Program из+b8,
проверяется Track+bb8. Исходное MIDI-событие и экспортная маска7ffffff8
сохраняются. Source0 проходит тот же обычный фильтр Sample, что и живой пэд.
Прежняя r19a меняла source, сохраняя переданную экспортёром дорожку+368;
прежняя r19c искала дорожки через реестр входных получателей. Ни один из
этих вариантов не считается рабочим аудиорешением по аппаратной пробе.

Новый check_resample_route.c выполняет реальные18b9a50,211aa30,2115070,
2119d00 и TrackInputFilter: пустой реестр не доставляет ноту, новый адаптер
доходит до обработки правильной дорожкой с MIDI60 иvelocity1. В тесте
подставлены конечная обработка дорожки, запись/MIDI-вывод и renderer;
наличие и причина отсутствия конкретных device-routes этим не доказаны.
Журнал r19d показывает track_changed/input_blocked/velocity для проверки.

Название Sample теперь задаётся отдельным scoped адаптером BL153edc8.
Native String возвращается через x8, имя источника копируется до вызова,
добавляется Resample, затем штатный pool выбирает свободный суффикс.
Для Seq и посторонних вызовов идёт исходныйf4ce00 без изменений.
Callsite/ABI/деструктор проверяются на настоящем ELF; названия секвенций
не меняются, отдельного постфактум переименования результата нет.
