# Ресэмплинг: проверка штатного назначения и Undo

Позднее26.10 отдельно выполнены настоящие создание RAM Sample и операции SamplePool, исправлен read-block ABI. Этот документ сохраняет границы предыдущего стенда назначения; текущий этап описан в [RESAMPLE_RAM_SAMPLE_RU.md](RESAMPLE_RAM_SAMPLE_RU.md). Общая Apply/Undo-транзакция ещё не собрана.

26 октября2026. Продолжение отдельного прототипа, после пятислотовой цепочки FX. Это ещё не сборка для MPC; r16d, autorun, архив и карта не менялись.

## Что добавлено

`src/pad_assignment.cc/.h` создаёт настоящую команду AssignSampleCommand прошивки1.3.0.12 и возвращает её как owned shared_ptr ABI pair. Подготовка не назначает сэмпл и не меняет параметры пэда. Native конструктор создаёт подписку на Program; native деструктор снимает её при окончательном освобождении команды.

Конструктору нужны настоящие ProjectProperties, Program, command service, SamplePool и уже зарегистрированный Sample. Проверяются:

- Цель0..127, слой0..7; массовое назначение во все слои здесь запрещено.
- Непустое имя, положительное число кадров, mono/stereo и допустимая частота дискретизации.
- SamplePool принадлежит переданным ProjectProperties, и поиск по имени возвращает именно этот Sample.
- Целевой instrument уже существует и принадлежит переданному Program. Этот адаптер не создаёт пустой instrument побочным действием подготовки.

Почему регистрация обязательна: настоящая команда сохраняет **имя**, а при Perform/Undo/Redo ищет Sample в библиотеке проекта. Неназначенный/удалённый из библиотеки результат нельзя считать готовым к Apply только потому, что есть PCM и поток чтения. Библиотека и зависимости должны оставаться живыми весь срок истории Undo; сам этот builder не регистрирует и не удаляет Sample.

`pad_assignment_release` освобождает только ссылку вызывающего кода. Если CommandManager сохранил свою ссылку, команда продолжает жить. При невалидном base ссылка сохраняется у вызывающего кода.

## Что реально исполняется в проверке

`verify_pad_assignment.py` компилирует ARM-код и запускает его в QEMU с закреплённым ELF и rootfs. Исполняются реальные функции:

| Адрес | Роль |
|---|---|
| `1995f90` | Конструктор AssignSampleCommand, копирование имени/состояния, подписка на Program |
| `199a3b0` | Perform: снимок восьми исходных слоёв и назначение результата в выбранный слой |
| `199af30` | Undo: восстановление назначений, включая исходные имена остальных слоёв |
| `199a290` | Преобразование SamplePool index и отправка параметров в Program |
| `199c2d0` | Деструктор команды, освобождение имён и снятие подписки |
| `19cf2b0` / `19d0a00` | Конструктор CommandManager и настоящий путь dispatch/проверки/выполнения команды |
| `286bbe0` / `2870e90` | Настоящие getters instrument выбранного пэда |

Проверены назначение слоя0 в другом банке, неизменность остальных семи слоёв при Perform, Undo/Redo, сохранение команды в истории после освобождения вызывающим кодом, окончательная очистка подписки и баланс ссылок на Sample. Отдельно проверены отказ для незарегистрированного/пустого результата, неверной цели/слоя и instrument другого Program.

**Явные границы стенда:** хранение SamplePool/истории и приёмник параметров Program заменены адаптерами. Получившийся звук не воспроизводится в настоящем sampler; создание Sample из PCM, сохранение файла и данные физического устройства не проверяются этим тестом. Данные Sample в тесте — fixtures, а не созданные native фабрикой объекты.

Отчёт: `build/resample-assignment/verification.json`, журнал: `build/resample-assignment/native-assignment.log`.

## Найденные ограничения следующего подключения

1. `SampleEditFunctions209b1f0` и предварительный шаг `2099800` используют очереди и future/wait. В пути обработки есть SampleLoader/хранилище (`1df5ee0`, `1d8ada0`). Это статический аудит; эти функции ещё не вызываются нашим модулем. Требуется установить владельца очереди и место хранения, не вызывать ожидающую операцию из UI и не блокировать очередь, которая должна исполнить её продолжение.
2. `ResetInstrumentCommand14912b0/14913b0` делает снимок instrument и вызывает полный reset `280f080`, затем восстанавливает отдельные поля. Это шире сброса запечённых стадий. Не подключать полный reset автоматически: нынешний renderer ещё не запекает Tune/огибающую/фильтр и не должен молча стирать их.
3. Этот builder — часть будущего Apply, а не весь Apply. Нужны создание/регистрация результата, проверка проекта/источника/цели под владельцем модели непосредственно перед commit, подтверждение перезаписи и объединение регистрации/назначения/нужных сбросов в одну проверенную Undo-транзакцию. При отмене не должно оставаться лишнего Sample в библиотеке.
4. Пока не проверен временный маршрут Original/Rendered в миксе. Назначение через Undo не использовать как частое переключение Compare: это засоряло бы историю и меняло проект при прослушивании.

Ближайшая работа — native создание и регистрация нового Sample с ограниченным временем жизни задания, затем связка с worker, сравнением и полным Apply. Только после этих проверок — отдельный пакет для аппаратной пробы.
