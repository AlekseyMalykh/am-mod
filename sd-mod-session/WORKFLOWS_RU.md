# r14e — Batch: жест входа, строки и прослушивание

Историческая инструкция r14e. Текущие назначения поиска, Preview Volume и Chop Batch описаны в [R15A_RU.md](R15A_RU.md) и [FEATURES_RU.md](FEATURES_RU.md); при расхождении использовать их.

Журнал возвращённой r14d подтвердил успешное копирование, удаление штатного Copy и освобождение собственного захвата пэдов. Несмотря на это, пользователь сообщил об отсутствии звука и Shift-команд до повторного Shift+Erase. На ARM воспроизведена другая причина: Shift-up с предыдущим номером окна терялся после B2. В r14e модификаторы проходят независимо от номера окна; нажатие, переданное штатной системе, получает парное отпускание даже через границу Batch.

На B2 передаются штатные отпускания Shift и Erase, сбрасываются запросы других модулей; последующие физические отпускания подавляются ровно один раз. Два конкретных штатных callback Erase-up временно сохраняют Copy как основу менеджера. При Cancel/Done явный выход в рабочей очереди удаляет Copy; вне Batch эти callback работают штатно. Проверены реальные native decoder/property и оба callback с их счётчиками времени жизни. Звуковой процессор стенда остаётся адаптером, аппаратное исправление ещё не подтверждено.

## Состояние

Сборка для аппаратной пробы. Прошивка 1.3.0.12, исходное приложение на устройстве не заменяется. EQ, ресемплинг и экспорт чопов в этот пакет не включены.

r14 показывала Batch, но проверка контекста отвергала окончательный штатный объект AC50CopyMode после завершения конструктора. r14a учитывает его базовую часть по смещению0x48 и итоговый vptr6e0dfd8. На ARM-стенде выполняется настоящий производный конструктор15173c0; проверено, что после смены vptr B2 открывает менеджер. При недоступном контексте/режиме вместо молчания показывается пояснение.

В аппаратной r14a менеджер открылся, но подтверждение четырёх копий вызвало SIGSEGV и восстановление штатного интерфейса. Журнал сообщает status11/SEGV и пик598.4МиБ; OOM-kill не зафиксирован. Найдена ошибка адреса: context68 уже содержит CommandManager, а мод ошибочно передавал его поле60. В r14b передаётся сам объект, как в штатном коде1518378. Добавлен ARM-тест настоящего диспетчера и рабочей очереди. Пользователь подтвердил в r14b копирование четырёх пэдов и групповую отмену. Подсветка целей и закрытие исходного Copy Pad работали неправильно; r14c исправляет их и требует новой аппаратной пробы.

## Chop / 16 Levels из Events и Steps

Одинаковая структура: звук и имя сэмпла; время события и velocity; Original / Selected; тип и номер выбранного пэда; K1 Type, K2 Choice, K3 Range. Чёрный фон, выбранное значение янтарное. B3 Apply, B1/B2 Cancel. До Apply исходное событие не меняется. Доступность по C/L сохранена. Обычные экраны игры в Sample этим изменением не переоформляются.

## Поиск Sample Select и Open Project

Shift + B3 открывает поиск. Сравнение латиницы без учёта регистра, совпадение по части имени. По умолчанию ищется библиотека Samples или Projects текущего накопителя, включая вложенные папки. Если открытый путь не содержит такой папки, область ограничивается текущей папкой с её подпапками. Выбранная область подписана сверху.

- Пэды вводят текст телефонной раскладкой. K1: Pads/Encoder. Энкодер и +/− меняют символ, K2 выбирает курсор, Erase удаляет символ. Пэд8: `. - _ #` последовательными нажатиями.
- **K3 в Query: Folder / Subfolders / Library**. Folder использует строки штатного браузера текущей папки; Subfolders обходит её подпапки; Library поднимается к содержащей папке Samples или Projects. Смена области сохраняет запрос.
- B2 переключает Query / Results. В Results энкодер, K2 и +/− выбирают файл. Под списком виден относительный путь выбранного результата, чтобы различать одинаковые имена.
- **В Results для Sample Select пэд выбирает место загрузки без воспроизведения и без загрузки**. Bank листает банки вперёд, Shift+Bank назад. Янтарный пэд — цель, красные — занятые, фиолетовые — свободные. Справа снизу Load to показывает A01…H16.
- **B3 Load** вызывает штатное действие выбранного режима: загрузку сэмпла в выбранный пэд либо открытие проекта. Для Samples в r14b ошибочно вызывалась ветка только для проектов; r14c использует отдельный штатный обработчик сэмплов. При отсутствии результата ничего не загружается. При занятом пэде действует штатный сценарий загрузки; для первой проверки выберите свободный.
- B1 Cancel возвращает браузер. Подпись Search обновляется при смене состояния Shift, в том числе после повторных поисков.

Обход только читает каталоги. Новые потоки не создаются: поиск выполняется порциями штатного UI-таймера. Ограничения:4096 файлов,512 каталогов, глубина16,50000 просмотренных записей; достижение границы отмечается в окне. Символические ссылки и скрытые имена пропускаются. Для рекурсивного поиска отбираются XPJ либо WAV/AIF/AIFF/MP3/FLAC/OGG, затем файл проверяет штатный загрузчик; это не добавляет поддержку новых аудиоформатов. В Folder остаётся фильтрация штатного браузера. Полный поиск по всему накопителю за пределами библиотеки не заявлен.

## Пакетное копирование пэдов

Штатный режим Copy (Shift+Erase), затем B2 Batch. Только в режиме Sample; это копирование звуков пэдов текущего проекта, не файлов между папками.

1. Выберите **до16 исходных пэдов**. Bank, K1, +/− листают банки без потери выбора. Выбранные источники зелёные, остальные заполненные пэды красные, пустые фиолетовые. Пустые источники не выбираются. Семнадцатый источник не добавляется: Selected 16 / 16. Для замены одного источника снимите с него выделение.
2. B2/B3 открывают Targets — таблицу Source → Destination. Первые назначения — свободные пэды, исключая выбранные источники. Энкодер выбирает строку. **Зелёный исходный пэд также выбирает его строку**, чтобы изменить путь копирования, и не назначается сам в себя.
3. **Нажатие другого пэда назначает его целью текущей строки**. Зелёные источники, фиолетовые свободные и красные занятые пэды видны во всём просматриваемом банке. **Все назначенные цели голубые; текущая цель выбранной строки янтарная.** Назначение имеет приоритет перед базовым цветом занятости/источника; занятая цель также отмечена `!` в таблице. Исходный пэд по-прежнему выбирает строку, даже если он назначен целью другой строки через кнобы. Пэды во время выбора не звучат. Bank меняет только просматриваемый банк, сохраняя назначения. В Sources +/− листают банки, в Targets +/− выбирают строки. Направления соответствуют штатным Plus0x36 / Minus0x37.
4. K1 задаёт банк автоматических назначений и перестраивает только строки Auto. Shift+K1 задаёт банк цели текущей строки. **K2: Auto, затем пэды1–16 просматриваемого банка**. На Auto строка освобождается от ручного закрепления, реальная цель показана в таблице. Erase тоже возвращает строку к Auto. **K3 содержит три режима**: First free — прежний поиск свободных с начала банка K1 по всем банкам; Same pad — подбор от номера источника с переходом по банкам; Bank free — дополнительный поиск только в банке K1. В Bank free при нехватке мест остаётся `--` и предупреждение: другие банки автоматически не используются. Измените K1 или выберите First free. Ручные назначения могут быть в других банках и сохраняются.
5. `!` у цели означает перезапись заполненного звука. Ручные назначения сохраняются. Уже закреплённая за другой строкой цель отклоняется; автоматически назначенная цель при ручном выборе освобождается и подбирается заново для другой строки. Копирование в себя отклоняется и при вводе кнобами, и перед применением. Выбрать другой исходный пэд как цель можно кнобами; его снимок сохраняется до записи.
6. Первое B3 показывает количество копий и перезаписей. Повторное B3 подтверждает всю операцию. **B1 Cancel отменяет менеджер и закрывает штатный Copy Pad целиком** с обеих страниц. B2 Sources возвращает к выбору источников внутри Batch. До подтверждения копирования звуки не меняются. После изменения строки требуется новое подтверждение.

После подтверждения сначала рисуется экран процесса. Штатная рабочая очередь последовательно подготавливает снимки источников, затем применяет копии **1/N…N/N**. Новый поток не создаётся. UI читает только атомарные счётчики, поэтому продолжает показывать индикатор. Быстрые стадии могут пройти между кадрами; искусственной задержки нет. **Done остаётся на экране до B1/B3**. После B1/B3 в r14e ставится выход из Copy в ту же штатную очередь, где выполняется обычное копирование. На короткое время показывается Closing Copy; затем освобождается захват пэдов. Такой же путь используется для Cancel из Sources/Targets и закрытия Failed. Это не новое копирование и не новая Undo-команда. При отклонении очередью остаётся понятное сообщение, выход можно повторить. Shift передаётся штатному обработчику и во время работы/выхода; его отпускание больше не блокируется менеджером. Во время работы повторное применение, изменение таблицы, глобальные команды и извлечение SD через интерфейс менеджера не выполняются. При Failed не повторяйте операцию до чтения журнала. Даже с индикатором карту нужно оставлять в устройстве до окончания операции.

Все источники снимком сохраняются перед первой записью, поэтому ручные пересекающиеся назначения, включая цикл, копируют исходные звуки. Применяются штатные CopyPadCommand, вложенные в одну Undo-команду. Undo отменяет всю группу, Redo повторяет. Аудиоданные сэмпла используются по штатным ссылкам CopyPadCommand: отдельные WAV-файлы этим действием не создаются. Настройки Orig Note / Lights привязаны к имени исходного сэмпла и продолжают использоваться.

В r15e на странице Targets добавлен **Shift + K3: Sound only / Sound + events**. По умолчанию Sound only. Во втором режиме события каждого исходного пэда дублируются на целевой во всех секвенциях, причём каждая секвенция сохраняет собственный рисунок. Время, длительность, velocity, C/L и mute сохраняются; исходные и существующие целевые ноты остаются. Общий Undo/Redo включает звуки и ноты. Все события снимаются до первой записи, лимит32768 новых событий. В Extract эта настройка отсутствует. Проверено ARM/QEMU; первая проба на MPC ещё требуется.

## Исправление Mute

В r13e–r13g использовалась неподходящая штатная remove/add-нормализация: изменение только признака mute могло превратиться в удаление. r14 передаёт карту замен штатному редактору событий, сохраняя количество, остальные параметры и дубликаты. Mute/Unmute, Undo/Redo проверены реальным ARM-исполнителем команд. Старые удалённые события автоматически не восстанавливаются. Возвращённые проекты сохранены в полной резервной копии карты, пользовательские проекты на карте не изменялись.

Заглушённый шаг остаётся фиолетовым при выборе и проходе курсора. Смешанная группа активных/заглушённых нот чередует зелёный и фиолетовый. Erase по-прежнему красный.

## Включение с заранее вставленной SD

Пользователь подтвердил обычную загрузку той же карты с переименованной папкой autorun. С включённым autorun зависание на0% возникает до предложения скрипта, то есть на этапе штатного обнаружения. Исправление этого случая **не заявлено**. Autorun восстановлен. Пока включайте MPC **без карты**, дождитесь штатного интерфейса, затем вставляйте SD и подтверждайте Start r14e.

## Проверки и ограничения

Компьютерный ARM-стенд исполняет штатные конструкторы/perform/undo Mute и CopyPadCommand, цикл A→B→C→A, нормализацию, исходные снимки и восстановление соответствия нот, дубликаты, отказ до записи при невозможности создать снимок. Для копирования реальные реестр проекта, клонирование аудио-инструмента и уведомления заменены адаптерами стенда. Проверены native optional<File>, isFile, общий callback загрузки, ввод, отмена, устаревшие события очереди, таблица назначений и границы рисования. В r14b аппаратно подтверждены четыре копии и Undo. Для r14c отдельно проверены настоящий обработчик загрузки сэмпла, рекурсивный поиск и производственный RGB-перехват с записывающим приёмником. Загрузка файлов, подсветка, закрытие Copy Pad и поведение новых областей на MPC ещё требуют пробы.


## Энкодер в таблице

Поворот и +/− выбирают строку, нажатие прослушивает её исходный пэд через обычный штатный audio input в той же рабочей очереди. Отпускание энкодера не обрывает короткий клик; Shift+клик останавливает прослушивание. Смена строки, Copy и Cancel тоже останавливают его. Выбранный звук проекта, банк, события и Undo этим действием не меняются. Seq Record должен быть выключен; нативный Record None проверяется перед постановкой в очередь и перед воспроизведением. Проверка аппаратного аудио ещё нужна. Энкодер больше не подтверждает Copy или экран Done.

## Массовый Extract — пока отдельный прототип

Вход только из обычного Chop при зажатом Shift: B1 — штатный Extract одного чопа, B2 — Batch, B3 — Split; Merge убирается с B3, Erase+пэд сохраняется. Copy Pad предназначен только для копирования звуков. Прототип общего менеджера выбирает до16 чопов, строит таблицу назначений и ставит последовательное извлечение в штатную очередь с прогрессом. Cancel/Done возвращают непосредственно в Chop, без закрытия несуществующего Copy. Реальное извлечение PCM и жизненный цикл SamplePool ещё не проверены, поэтому в autorun r14e прототип выключен.
