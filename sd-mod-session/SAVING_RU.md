# r9h: диагностика внешнего сохранения

## 24 октября: карта пересоздана, причина предыдущего отказа найдена

Журнал r9h показал: samp и prod сохранялись на старый Linux-раздел №7 этой SD, тогда как загрузчик разрешал папки на exFAT-разделе №1. fopen сэмпла и mkdir данных проекта получили errno30 (read-only). Прогресс сохранения проекта не означал успех. На карте оставалось семь разделов Anbernic; Windows показывала только первый как D:.

По прямому запросу пользователя все старые разделы удалены. Теперь один GPT-раздел exFAT с меткой MPCMOD, объём файловой системы 62 234 034 176 байт (около 58 ГиБ). Записана та же r9h с диагностикой. 48 доступных файлов старого D: сохранены и сверены; побайтовой копии других шести разделов нет. Новая карта ещё не проверена на MPC.

Следующая короткая проба: полностью перезапустить MPC без SD, вставить карту, запустить r9h, сохранить samp и prod на External, затем Mod Off и открытие реальных файлов с карты в штатном интерфейсе. Перед переносом из Windows — «Извлечь». Старые разделы удалены, прежние пути UUID больше использовать нельзя.


## Состояние

Сохранение сэмпла в Internal и его ручное удаление на r9f подтверждены пользователем. Internal — RAM, данные исчезают после Mod Off. Сэмпл в External на r9g по-прежнему выдаёт Sample Save Failed. Проект example-kit был отмечен пользователем как сохранённый, но файл не найден на всей возвращённой SD; долговечность не подтверждена.

Штатное окно Save Sample выбирает только Internal/External ручкой K3. Произвольную папку в нём выбрать нельзя. Прежняя инструкция с Mod-Saves была неверной.

В r9g и r9h разрешённые области записи: `MPC-Sample/Projects` и `MPC-Sample/Samples`. Подкаталог Samples/User уже охвачен. Журнал r9g подтвердил доступность обеих папок в namespace, но этого недостаточно для объяснения реального отказа.

## Короткая проба r9h

1. Извлеките карту из Windows через «Извлечь», дождитесь подтверждения, затем перенесите её в полностью перезапущенный без карты MPC.
2. Подтвердите **Start r9h save diagnostics** и после загрузки проверьте наличие Mod Off.
3. Один раз сохраните короткий сэмпл через Shift + Sample Select / Save Sample, K3 → External, новое имя **R9H_SAMPLE_01**. Запишите сообщение о результате.
4. Один раз сохраните небольшой проект через Project → Save Project, External, новое имя **example-kit_H**. Не перезаписывайте прежние файлы.
5. Дождитесь завершения операции, затем Mod Off → штатный Eject → карта в ПК. Проверим полный журнал и файлы. Сообщение об успехе не считается подтверждением записи на SD.

В этой сборке не нужно проводить длительную сессию. Если интерфейс не вернулся автоматически после сбоя, сообщите об этом; запасная сборка r9g сохранена в локальном архиве.

## Диагностика

Встроена отдельная read-only библиотека в namespace клона. Она регистрирует выбранные libc-вызовы open/fopen, mkdir, rename, unlink, access/euidaccess/faccessat и до 16 вызовов statfs с флагами файловой системы. Исходные аргументы, результаты и errno сохраняются. Это не перенаправление сохранений и не предоставление дополнительных прав. Журнал ограничен 1024 записями в RAM, без процесса/потока наблюдения. Прямые syscalls и другие APIs могут не регистрироваться. Влияние перехвата на производительность ещё не измерено на MPC.

Read-only снимок mountinfo и объектов штатной службы дисков покажет, какой накопитель видит клон. Перед остановкой дополнительно перечисляются до 128 файлов временного RAM upper с глубиной до восьми каталогов. В полном отчёте после Mod Off будут секции save-io.txt и save-storage.txt. Там могут быть пользовательские имена файлов; отчёт хранится локально и в резервной копии карты, в Git он не публикуется.

Права приложения, лимит слоя 512 МиБ, штатный резерв 400 МиБ и MemoryMax 800 МиБ не меняются. Внутренний накопитель остаётся read-only под RAM OverlayFS. r9h ещё не проверена на устройстве; причина ошибки внешнего сохранения пока не объявлена установленной.
