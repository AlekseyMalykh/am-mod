# Ресэмплинг: контекст приложения и открытие/закрытие на очереди

Продолжение r17: intrusive lifetime hook каждого runtime останавливает wake/repost его очереди до native деструктора. Тесты покрывают queued и уже исполняющийся callback (отдельный pthread), немедленный Cancel во время чтения/DSP/подготовки RAM Sample и после dispatch. Контекст не ждёт работу UI; native счётчик продолжает учитывать текущую задачу. Подробности и ограниченная первая проба: [RESAMPLE_UI_RU.md](RESAMPLE_UI_RU.md), [R17_RU.md](R17_RU.md).

Продолжение: lifecycle/input/paint hooks теперь установлены только в отдельной экспериментальной библиотеке. Настоящий деструктор дополнительно проверен с отложенным открытием; осиротевший runtime удерживается до окончания процесса, чистый dlclose не заявляется. Полное выключение активной обработки ещё не проверено. Текущий статус: [RESAMPLE_UI_RU.md](RESAMPLE_UI_RU.md); ниже сохранён предыдущий этап.

26 октября 2026. Продолжение прототипа очереди/панели. Рабочая r16d, autorun, архив и карты не изменялись. Физические обработчики входа Shift + пэд 11 и отрисовки ещё не установлены.

## Захват на владельце модели

`src/resample_context.cc/.h` читает закреплённую структуру базового подобъекта AC50CopyMode: конструктор `1518980`, vptr `6d8cd88` или `6e0dfd8`, а не адрес полного производного объекта. Положение полей проверено по исходному ELF 1.3.0.12:

| Поле контекста | Значение |
|---|---|
| `+48` / `+50` | Штатная очередь / счётчик ожидающих задач |
| `+68` | CommandManager, vptr `6d97818` |
| `+70` | Сервис очереди для внутренней команды назначения |
| `+78` | CurrentThings: Program `+b8`, выбранный instrument `+60` |
| `+c8` | ProjectProperties: SamplePool `+1278` |

Захват выполняется только на штатном владельце модели, под её обычным исключением. Номер пэда вычисляется настоящим getter `286bc20`; принадлежность instrument к Program проверяется. Из настоящего Sample читаются имя и сервисы. Сканирование занятости учитывает все восемь слоёв каждого пэда. Отсутствующий/непринадлежащий библиотеке Sample и несовпадающий контекст отклоняются. Длинное имя сокращается на границе UTF-8.

Тест использует адаптированный набор полей контекста с настоящими Sample/Pool/getters. Полный конструктор CopyMode со всем service registry не эмулируется; его базовый конструктор и настоящий деструктор исполняются отдельно.

## Почему отдельный счётчик времени жизни

Деструктор native CopyContext `1517c70` ждёт обнуления `context+50`, отменяя/завершая задачи по тегу очереди. Поэтому история Undo не должна держать этот счётчик на всём протяжении своей жизни.

Новый tracker имеет собственный счётчик ссылок и поколение проекта. Native очередь удерживает `context+50` только для своих callbacks; Capture/adapter/история удерживают tracker отдельно. Перед сменой проекта вызывается `resample_context_changed`, перед уничтожением native контекста — `resample_context_stop`. Проверки live/generation выполняются до чтения сохранённых указателей.

Tracker **не продлевает физическое время жизни native сервисов или модели**. Хост обязан сериализовать смену проекта с владельцем модели и сохранить штатный порядок очистки истории до её native зависимостей. Одних атомарных флагов недостаточно для произвольного параллельного уничтожения проекта. Реальное подключение этих lifecycle hooks пока не выполнено.

В проверке tracker останавливается до вызова настоящего деструктора `1517c70`; деструктор завершается при ещё существующей команде истории и нулевом счётчике очереди. Затем tracker освобождается владельцем, а оставшаяся ссылка истории безопасно отклоняет работу по старому контексту. Это не проверка полного выключения физического устройства.

## Восстановление после частичного Undo

Команда истории теперь содержит собственную intrusive-ссылку для quarantine. При передаче команды обработчику отказа не выделяется новая память и не вводится лимит числа одновременно удержанных команд.

`resample_context_finish_recovery` достаёт одну команду и просит существующий механизм проверить восстановленное состояние. Если хост ещё не вернул исходные назначения, команда остаётся удержанной. Автоматического восстановления модели здесь нет. Проверены две команды одного Capture, их независимые ссылки и последовательное освобождение после явного восстановления стендом.

Нельзя ждать такого восстановления внутри native деструктора. Чистая выгрузка модуля должна отдельно проверять наличие quarantine и действительный порядок жизни зависимостей; завершение всего процесса не равнозначно проверенной чистой выгрузке.

## Новый runtime окна

`src/resample_runtime.cc/.h` управляет переходом между UI и очередью:

1. UI создаёт запрос открытия и показывает подготовку; модель на UI не читается.
2. Callback штатной очереди захватывает выбор, создаёт native adapter/worker и публикует готовую пару вместе с копией имени/номера пэда.
3. UI связывает панель с готовым worker. Команды передаются копиями, прогресс — числовыми снимками.
4. Cancel сохраняет окно до подтверждения отмены. При успешном Apply сохраняется признак Applied и доступная история Undo.
5. После закрытия панели отдельный callback владельца уничтожает worker/adapter. UI может уничтожить runtime только после этого подтверждения и освобождения очереди.

Отмена до захвата вообще не создаёт обработчик. Неудачный захват можно закрыть и повторить. Отказ отправки в полную/остановленную очередь сохраняет один запрос для повторения таймером. Play/Stop и обе границы Shift передаются штатному приложению. Отпускание кнопки, захваченной панелью, поглощается и после закрытия, чтобы не вызвать действие в следующем штатном окне.

Запрос Seq выдаётся хосту только после полного завершения очистки. Выбор/редактирование FX выдаёт запрос и номер слота; конкретный экран редактирования и штатный переход в Seq ещё обязан подключить физический UI-хост. Сам runtime не синтезирует неизвестные коды кнопок.

## Проверки и оставшаяся работа

`verify_resample_native.py` и `--ubsan` проходят расширенную цепочку: предыдущие проверки Sample/Pool/очереди/истории, захват контекста, реальный native деструктор, отказы stale/poisoned указателей, несколько recovery-команд, асинхронный runtime, Cancel до создания worker, неудачный захват/повторное открытие, FX/Seq запросы, Apply/Undo/Redo, owner teardown и позднее отпускание Cancel. Дополнительно выполнены 20 циклов открытия/рендера/отмены с настоящей native очередью на отдельном pthread; UI только отправляет команды и читает обновления.

Дополнительно повторены `verify_pad_resample_commit.py` и `verify_resample_flow.py`. Native ELF не инструментирован UBSan, физический sampler и накопители не проверяются стендом. Первичная очередь/поля контекста, приёмники параметров инструмента и хранение истории остаются адаптерами там, где это указано в отчёте.

Далее нужно установить реальные lifecycle/input/paint hooks, подключить редактор EQ/переход Seq и проверить конфликтующие модальные окна. Перед аппаратной пробой остаются проверка фактического порядка выхода/выключения, воспроизведение sampler и сохранение/reopen. Сравнение в миксе, современные native FX и запекание Tune/огибающей/фильтра не считаются выполненными.
