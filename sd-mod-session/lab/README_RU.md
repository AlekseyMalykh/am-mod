# Виртуальная лаборатория MPC Sample

Установлена в Ubuntu/WSL: `/opt/mpc-sample-lab`.
Исходники: [orrpunk-art/virtual-mpc-sample](https://github.com/orrpunk-art/virtual-mpc-sample)
(проверено с состоянием на 29.10.2026).

Это QEMU с настоящим приложением MPC Sample 1.3.0.12 и браузерной панелью.
Старая папка `virtual-mpc` в нашем репозитории содержит другую, браузерную модель.

## Запуск в Windows

Из этой папки:

```powershell
.\Start-MpcLab.ps1 -OpenBrowser
```

Панель: <http://127.0.0.1:8765/>. QEMU работает в фоне.
Карта штатных экранов из эмулятора: <http://127.0.0.1:8766/index.html>.
Это отдельный справочник, который работает и без QEMU:

```powershell
.\Open-StockMap.ps1 -OpenBrowser
```

Оригинальный самодостаточный файл находится в
`/opt/mpc-sample-lab/stock-map/index.html`. Обновление также включает передачу
байтов виртуального UART с темпом реального контроллера. Сервер панели был
перезапущен для применения этого изменения; QEMU не заменялся.

Штатное завершение виртуального устройства:

```powershell
.\Stop-MpcLab.ps1
```

Вход в Linux виртуального устройства:

```powershell
wsl -d Ubuntu -u root --cd /opt/mpc-sample-lab -- python3 lab.py ssh
```

## Проверка пакета мода

Дождаться полной загрузки обычного интерфейса, затем вставить виртуальную
SD-карту со сборкой через лабораторию. `--no-reboot` соответствует нашему
порядку запуска на реальном устройстве: сначала загрузка, затем карта.

```powershell
wsl -d Ubuntu -u root --cd /opt/mpc-sample-lab -- python3 lab.py autorun "<workspace>/mpc-sample-r21c-lighting-power-audit.zip" --no-reboot --yes
wsl -d Ubuntu -u root --cd /opt/mpc-sample-lab -- python3 lab.py autorun --results
```

Перед следующей сборкой выйти из мода через Project → Mod Off; для чистой
проверки перезапустить виртуальное устройство. У лаборатории отдельный файл
карты, она не обращается к физическому диску D:.

## Устройство установки

- Все четыре входных файла проверены по штатному `inputs.sha256` лаборатории.
- Исходные образы прошивки подключаются только для чтения; виртуальная eMMC
  использует собственный qcow2-диск и отдельный слой лаборатории.
- Готовые образы и журналы сборки: `/opt/mpc-sample-lab/out`, `build.log`.
- QEMU 9.2.4 собран из официального архива `download.qemu.org` в
  `/opt/mpc-sample-lab/qemu`. Системная QEMU 8.2 не создаёт второй PL011,
  необходимый лаборатории; запускатель выбирает частную версию через PATH.
- Исправлен чистый запуск сборки образов: создание `root/.ssh` до установки
  публичного ключа. Патч: `patches/0001-create-ssh-directory.patch`.
- Штатная библиотека `/content` не входит в обновление прошивки и здесь пока
  отсутствует. Для тестирования можно загрузить свои WAV в виртуальную карту.
- Сборка инструментов выполнена в Docker Desktop. Для следующей пересборки
  из Ubuntu используются Linux CLI Docker и сокет интеграции Ubuntu:

```sh
cd /opt/mpc-sample-lab
PATH=/mnt/wsl/docker-desktop/cli-tools/usr/bin:/usr/bin:/bin \
DOCKER_HOST=unix:///mnt/wsl/docker-desktop/shared-sockets/guest-services/Ubuntu.docker.container-proxy.sock \
python3 lab.py build
```

На этом x86-компьютере проверка песочницы загрузчика занимает более 20 с,
поэтому в **слое лаборатории** увеличены TimeoutStartSec пробы до 180 с и
начальный срок ожидания клона до 600 с. Проверка состояния работающего
клона сохранена. Эти изменения отсутствуют в пакете для SD настоящего MPC.
Файл `prepare_tcg.py` позволяет применить ту же настройку к уже запущенному
чистому гостю. При проверке холодного запуска она включена в lab-layer.

Минимальная сборка QEMU не включает PNG. Сервер панели локально дополнен
преобразованием PPM в PNG; патч хранится в `patches/`. Также сохранён патч
нормального завершения QMP, когда QEMU закрывает соединение после `quit`.

Для проектов с большим числом звуков маленькой autorun-карты 64/128 МБ
недостаточно: приложение учитывает собственный резерв места. В лаборатории
используется отдельный exFAT-образ 2 ГБ. `create_large_card.py` создаёт его
только из обычного файла и проверяет привязку loop-устройства; физические
диски не принимаются. Образ: `out/run/lab-large-card.img`.

Репозиторий содержит `scripts/con.py`, поэтому его рабочая копия находится
на файловой системе Linux: Windows запрещает такое имя файла.

## Что здесь можно проверять

Окна и диалоги настоящего приложения, кнопки и сочетания, подсветку пэдов,
события секвенсора, SD autorun, загрузку/сохранение файлов и программный
звуковой тракт. Для взаимодействия есть документированный HTTP API панели,
снимки `/screen.png` и SSH гостевой системы.

На x86 ARM исполняется программно. Скорость, задержки и стабильность аудио
не являются измерениями реального MPC. Батарея, зарядка и полный тракт USB
audio здесь не воспроизведены. Проверка в лаборатории не заменяет конечную
проверку на устройстве.
