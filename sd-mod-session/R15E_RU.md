# r15e — копирование звуков вместе с событиями

## Как выбрать режим

Sample → Shift + Erase → B2 Batch → выбрать исходные пэды → Targets.
На странице Targets **Shift + K3** выбирает:

- **Sound only** — только звук, как раньше. Это значение по умолчанию при каждом открытии Batch.
- **Sound + events** — звук и его события во всех секвенциях текущего набора звуков.

Обычный K3 сохраняет First free / Same pad / Bank free. После отпускания Shift выбранный режим событий сохраняется; заголовок становится COPY PADS + EVENTS. Назначение целей, предупреждение о перезаписи и подтверждение B3 остаются.

Каждая секвенция сохраняет свой рисунок: A01 → B01 дублирует события A01 из Seq A на B01 в Seq A, а события A01 из Seq C — на B01 в Seq C. События между секвенциями не перемещаются. Исходные ноты и существующие ноты цели сохраняются. Копируются время, длительность, velocity, mute и сохранённые модификаторы Chop/16 Levels. В режиме Sound only события не меняются. Для Batch Extract эта настройка не применяется.

Все исходные события и звуки фиксируются перед первой записью. Поэтому пересекающиеся назначения копируют исходные данные, а не результат предыдущей строки. Один Undo отменяет звуки и добавленные ноты; один Redo повторяет. Ограничение — до 16 звуков и 32768 новых событий за одну операцию. Превышение лимита отклоняется до записи.

## Поиск и прослушивание

B3 Preview в результатах поиска теперь включает/выключает автоматическое прослушивание. Когда включено, прокрутка запускает выбранный аудиофайл, остановив предыдущий. При выключении, выходе из поиска или переходе к вводу прежнее прослушивание останавливается. K3 и Main используют уже проверенный на устройстве путь регулировки громкости.

В Copy/Extract при смене строки, страницы, банка или назначения отправляется остановка текущей пробы. **Исправление однократного проигрывания Loop-сэмплов ещё не закончено:** обычный Note Off не доказывает принудительную остановку Loop, а таймер по исходной длине неверен при изменении высоты/скорости. Настройки Loop источника и копии не менялись. Прослушивание чопов в Batch временно отключено после сообщения о сбое r15c; Extract остаётся доступен. Проверять нажатие энкодера для чопов повторно не нужно.

Возвращённый журнал r15c относится к более позднему штатному завершению через Mod Off. Он подтверждает успешное копирование четырёх пэдов, но не содержит описанного сбоя, поэтому его точная причина пока не установлена.

## Что проверено

ARM/QEMU исполняет настоящие функции прошивки для получения трёх секвенций и их списков событий, создания/выполнения/отмены команды событий и CopyPadCommand. Проверены разные рисунки по секвенциям, дубликаты, C/L/mute, существующие целевые ноты, Sound only, пересекающиеся назначения и общий Undo/Redo. Проверка не воспроизводит физический аудиодвижок и экран MPC. Новая r15e ещё не проверена на устройстве.

## Первая проба

1. Безопасно извлечь SD из Windows. Загрузить MPC без карты, затем вставить SD и подтвердить **Start r15e**. Проблема холодного включения с autorun остаётся открытой.
2. В тестовом проекте записать на A01 разные короткие рисунки в двух секвенциях.
3. В Batch назначить A01 → свободный B01, в Targets выбрать Shift + K3 → Sound + events и подтвердить B3 дважды.
4. Поочерёдно проверить обе секвенции: на B01 должен появиться рисунок A01 именно из текущей секвенции; A01 остаётся. Один Undo должен отменить всю операцию.
5. Выход: Project → Mod Off → штатный Eject. До завершения операции карту оставлять в устройстве.

Установленная прошивка не обновляется. Новая сборка запускает приложение в RAM. Пользовательские файлы на SD при обновлении не удаляются.
