## 25 октября: r15 — Batch Extract включён для первой аппаратной пробы

В Chop удержать Shift: B1 штатный Extract, B2 Batch, B3 Split. Выбор до16 чопов, общая таблица назначений, последовательное извлечение отдельных обрезанных сэмплов, прогресс, защита источника и одна Undo-команда. Начальная проба — два коротких среза на свободные пэды. Инструкция: [R15_RU.md](R15_RU.md). Сохранение/повторное открытие нового результата на устройстве ещё требует проверки.

Отказ Mute в r14f подтверждён пользователем. r15 проверяет флаг на входе секвенции и в отдельном маршруте внутреннего сэмплера, которые обходили прежний фильтр. Это новое исправление требует аппаратной пробы; старые записи о готовности r14f не являются подтверждением звучания Mute.

# Прототип следующего этапа: экспорт Chop на пэды

Пользователь выбрал отдельные обрезанные сэмплы, а не ссылки с Trim. В autorun r14e экспорт выключен: MPC_EXPERIMENTAL_CHOP_EXPORT=0. Прототип собирается отдельно с флагом1. На карту он не установлен.

## Подтверждённый штатный механизм 1.3.0.12

- ExtractSliceCommand vptr6e42758, native perform19aaae0, undo19a9820. Подготавливает отдельный сэмпл через SampleEditFunctions209c5b0; параметры среза сохраняются native2949a80, не извлекаются из пикселей волны.
- ExtractAndAssignSampleCommand vptr6e07640, ctor143ed40, perform143f0b0, undo143ee90. Уже объединяет извлечение и назначение на конкретный пэд. Вход ctor: имя, индекс назначения, SliceData*, исходный Instrument*, Project*, SampleEditFunctions*, SampleLoader*, ThreadQueues* в девятом аргументе стека.
- Штатный UI SampleModeScreen16580d0 сначала находит свободный пэд через Program286dd00 и подготавливает его параметрами исходного звука280f130. Прямой вызов этого UI-handler не подходит для ручной таблицы и единой отмены: нельзя выполнять подготовку целевого звука до подтверждения.
- SliceData snapshot2949a80 читает start78/endd0/loop128/crossfade180/mode1d8/type230/float2e0/float338/extra288. Native ctor2949dd0, copy294bca0, destructor294a7f0. План — отдельные принадлежащие операции снимки каждого выбранного среза.

## Интерфейс и порядок операции

Вход **непосредственно из Chop** при удержании Shift:

- B1 — штатный Extract одного чопа.
- B2 — Batch выбранных чопов, вместо Split.
- B3 — Split, вместо Merge. Erase+пэд сохраняет штатное удаление/слияние с предыдущим.

Copy Pad → B2 Batch остаётся отдельным менеджером звуков. Технический вход Slices из Copy Pad удалён даже в прототипе. Менеджер чопов использует обычный экран Sample/Chop; Cancel и Done возвращают туда, не вызывая выход из Copy. Перенаправление B3 в штатный Split/B2 парно для нажатия и отпускания, в том числе после отпускания Shift и изменения поколения окна. В остальных режимах верхние кнопки работают штатно.

Предел — **16 выбранных чопов** за операцию, в UI и исполнителе. Семнадцатый не выбирается. Общий набор может содержать больше16, просмотр страниц сохраняет выбор.

Выбор нескольких чопов пэдами; если исходный сэмпл содержит больше16 срезов, K1 и +/− листают страницы по16 без потери выбора. Затем общая таблица Slice → Destination: свободные назначения, ручные строки, предупреждение о заполненных целях, двойное подтверждение. Исходный пэд запрещён как назначение. Обычный Batch звуков сохраняется отдельно.

- B2/B3 после выделения открывают таблицу. Энкодер выбирает строку.
- K1 меняет банк автоматических назначений; Shift+K1 — банк назначения выбранной строки; K2 — номер целевого пэда.
- Ручное назначение закрепляется. Erase возвращает строку к автоматическому подбору. K3 — First free / Same pad / Bank free, как в менеджере звуков.
- Занятый целевой пэд обозначается `!` в таблице и красной подсветкой. Перед применением B3 показывает число перезаписей; повторное B3 подтверждает.
- Совпадающие назначения не применяются. B2 возвращает к выбору источников. B1 Cancel закрывает менеджер с любой страницы и возвращает в Chop.

Перед записью захватить все срезы и проверить назначения. Для строки выполнить штатный CopyPadCommand (сохраняющий старый целевой звук для Undo), затем ExtractAndAssignSampleCommand. Всю группу объединить в одну Undo-команду. При ошибке вернуть уже изменённые пэды и убрать созданные этой операцией сэмплы штатными Undo-путями. Имена уникализировать через Project SamplePool292f0e0, не перезаписывать одноимённые WAV. Исходный сэмпл и его маркеры не изменять.

## Выполнено в исходниках, не записано на карту

Новая асинхронная операция batch_chop_begin использует общий с Copy механизм очереди. Сначала UI рисует прогресс; затем выполняются последовательные native команды, без нового потока. Реальное извлечение не запускается в paint/button обработчике. Done сохраняется до подтверждения. ARM-стенд интерфейса проверяет Shift+B1/B2/B3 непосредственно в Chop, парное отпускание Split, предел16, прогресс до постановки задачи и возврат Cancel/Done без Copy modal. Пока исполнитель PCM в тесте заменён адаптером. Контекст сервисов берётся из штатного CopyMode; доступность его полного жизненного цикла при первом входе непосредственно в Chop нужно проверить до включения на устройстве.

Прототип интерфейса и групповой команды собирается с -Werror. ARM-стенд выполняет реальные native CopyPadCommand ctor/perform/undo, SliceData ctor/copy/dtor и ExtractAndAssignSampleCommand ctor/destructor. Проверены аргументы двух сервисов и девятый аргумент стека, выбор до16 в разных банках/страницах, отказ на17, назначения и защита исходного пэда. Проверены групповая Undo/Redo, ошибка второго извлечения и откат частичного результата, созданного до Assign. Исполнение извлечения и PCM в этих проверках **заменены адаптерами**, это не доказательство готовности аппаратного экспорта.

Первый прототип ограничивает сумму вновь создаваемых аудиоданных 64МиБ при консервативном расчёте8 байт на кадр; число срезов само по себе не гарантирует достаточный объём RAM. Новые имена формируются с номером исходного пэда и чопа и проверяются native SamplePool. Исходные настройки Orig Note/Lights привязаны к старому имени и пока автоматически не переносятся на новые сэмплы.

Остаются проверки реального извлечения PCM, точных границ, stereo, файлового пути нового сэмпла, исчерпания памяти/места, Undo/Redo с настоящим SamplePool, сохранения проекта на External и открытия в штатной прошивке. До этого прототип не упаковывается в autorun и не заменяет установленную r14e.

Отдельная проверка прототипа: WSL Ubuntu, `python3 verify_chop_prototype.py`. Она сохраняет отчёт в build/r15-prototype-verification.json и не изменяет autorun, архив установленной сборки или карту.


## Дополнительная проверка отказа —25 октября

В стенде добавлен вызов настоящего ExtractSliceCommand::perform19aaae0 и настоящего SampleEditFunctions209c5b0 до границы создания Sample. Для режима1 адаптер создания специально возвращает пустой результат. Проверено: штатный код возвращает ошибку3, не назначает выходной Sample, исходный маркер не меняется. Источник аудио и отказ создания Sample здесь адаптеры; режим2 с настоящей обрезкой, успешный PCM, сохранение и реальный SamplePool по-прежнему не проверены. Этот тест не разрешает включение функции на карте.

При первом прямом входе из Chop нужно ещё проверить готовность штатного CopyMode-контекста, из которого сейчас берутся сервисы/рабочая очередь. Обнаружение Chop, верхние кнопки и возврат из менеджера уже проверены отдельно.


Статическая проверка конструктора набора режимов: единственный прямой вызов AC50CopyMode15173c0 находится в14ae920; память148 выделяется в14ae90c, объект сохраняется в owner+310 в14ae928 до создания соседних режимов. Это указывает, что контекст строится с остальными режимами, а не только при открытии Copy Pad. На устройстве ещё нужно подтвердить его захват при старте и совпадение CurrentThings при первом входе из Chop; требование предварительно открывать Copy в интерфейс не добавлялось.


## Проверка потока реальной обрезки — 25 октября

В check_chop_pcm.c выполнены настоящие AudioReadStream/TrimProcessingStream ctor, native SampleData copy/refcount, read/seek/EOF и деструкторы. Источник — детерминированные stereo PCM-кадры тестового адаптера. Проверены средний диапазон4..12, весь0..16, однокадровый15..16, точные первый/последний кадры обоих каналов, отказ seek за границу и неизменность метаданных источника. Проверка включена в verify_chop_prototype.py. Это подтверждает native обрезку, но не создание/регистрацию готового Sample, экспорт WAV или сохранение проекта. Прототип остаётся выключен и в r14f.
