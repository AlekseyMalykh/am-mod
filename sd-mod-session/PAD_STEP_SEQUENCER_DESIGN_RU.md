# Предложение: Pad Steps и расширение штатного Step Edit

Статус: проект интерфейса, 24.10.2026. Не реализация прошивки. Пользователь уточнил: Copy/Paste и переходы по тактам нужны в штатном Step Edit с отдельными событиями. r12b и карта этим документом не изменяются.

## Опора на штатные возможности

Официальный Step Edit: вход Shift+SEQ, энкодер двигает позицию по Q, +/− выбирают события текущего шага, фейдер меняет время события, K1 — длина секвенции, K2 — Q, K3 — velocity; удержание B1 открывает темп, B3 удаляет выбранное событие. Документированной функции B2 на этой странице нет; отсутствие других привязок ещё проверить в бинарнике 1.3.0.12.

Основной Sequence Mode и Step Edit — разные экраны. В основном Seq B2 переключает SEQ/GBL BPM. Предлагаемый вход B2 расположен **в Step Edit**; основная кнопка темпа Seq сохраняется.

В локальном ELF обнаружены AC50StepEditController, SequenceEventListListener и SafeLifetime::Holder<UnsafeSequenceEventList>; StepEditScreen есть в существующем UI-аудите. Это подтверждает наличие штатной модели, но не готовую безопасную команду вставки. Адреса/контракты Add/Delete/Clone/Undo ещё нужно установить.

## Два представления одних событий

- **Events:** существующий Step Edit с точным выбором отдельных нот.
- **Steps:** 16 временных позиций выбранного звука на физических пэдах.
- B2 переключает Events ↔ Steps и сохраняет позицию и выбранный звук. Новый режим не создаёт отдельную секвенцию и не требует включать REC.
- Кнопки SAMPLE/SEQ и выход в другое окно прекращают захват шаговых пэдов. Меню именования получает свой прежний приоритет.

## Управление Steps

| Контрол | Предложение |
|---|---|
| Пэд без Shift | Пустой слот: добавить ноту. Одна обычная нота: выключить её. Несколько нот: выбрать группу без массового удаления |
| Shift+пэд | Выбрать звук в текущем банке без воспроизведения и без изменения рисунка |
| +/− | Следующая/предыдущая страница16 шагов, без изменения транспорта |
| Shift+/− | Штатные Undo/Redo |
| Энкодер, фокус Step | Выбрать шаг без добавления/удаления; при переходе границы открыть его страницу |
| Shift+вращение, фокус Step | Перейти на такт назад/вперёд с сохранением позиции внутри такта |
| Клик энкодера | Фокус Step → Sound → Grid → Velocity; Shift+клик — назад |
| K1 | Sound: выбор одного из 16 звуков текущего банка, например A01–A16; на границах выбор ограничен, без перехода в соседний банк |
| Shift+K1 | Bank: выбор A–H с сохранением номера звука внутри банка, например A03 → B03 |
| K2 | Grid: отображаемая сетка, сначала1/16, затем1/8,1/32 и триоли |
| K3 | Velocity выбранной ноты либо значение для новых нот, если слот пуст |
| Фейдер | Микросмещение одной выбранной ноты, по штатному пути |
| B1, удержание | Штатное редактирование BPM |
| B2 | Вернуться в Events |
| Shift+B2 | Follow on/off в Steps |
| B3 | Edit: меню операций события Copy / Paste / Paste to Pad / Note Length; отдельное удаление на B3 в Steps исключено |

Уточнение пользователя от 24 октября: в Events K1/K2/K3 и +/− остаются штатными, +/− выбирают события списка. Энкодер листает позиции по кругу всей секвенции. Shift+энкодер перемещает выбранное событие по сетке штатного Q с сохранением его свойств; нота и просмотр переходят по кругу между концом и началом секвенции. Если выбранного события нет, перемещается только просмотр. Это заменяет раннее предложение перехода по тактам Shift+энкодером в Events. В Steps Shift+энкодер с фокусом Step остаётся навигацией по тактам. BPM/модальное окно сохраняют приоритет штатного управления.

Новые сочетания B2, Shift+B2, B3 в Steps, Shift+B3 в Events, Shift+K1 и Shift+энкодер — предварительные: перед реализацией проверить все штатные привязки и приоритеты. В интерактивном макете Events представлены выбор событий и операции буфера; штатные K1 Length и K2 Q показаны как значения без имитации полного родного редактора.

По замечанию пользователя отдельное удаление на B3 в Steps убрано: обычная нота включается/выключается пэдом. Штатные функции ERASE нужно сохранить с их точным контекстом, не подменяя очистку всех событий звука удалением одного события. Точный выбор/удаление сложного события остаётся в Events. Энкодер с фокусом Sound повторяет K1: без Shift — 16 звуков, с Shift — банк; смена звука/банка только выбирает дорожку для просмотра и не переносит её ноты.

**Grid желательно отделить от Q записи/RT Swing.** Изменение масштаба Steps не должно менять Q, свинг или автоматически квантовать существующие ноты. Для первой реализации можно начать с фиксированной1/16; расширение сеток разрешать только после разбора точного времени событий. В Events сохраняется штатный Q.

PAD BANK штатно циклически выбирает A–H, Shift+PAD BANK — предыдущий банк. Это банк звуков, а не временная страница. Штатный Bank+Pad1–8 — ещё один потребитель пэдов: для первого варианта Steps предлагается его подавить; банк доступен кнопкой или K1. Если сохранять этот быстрый выбор, он должен быть отдельным явным состоянием, которое никогда не добавляет ноты.

## Пэды и курсоры

Предлагаемое значение красного: **позиция воспроизведения**. Выбранный шаг редактирования — янтарный; при остановке они могут не совпадать. В макете предусмотрен вариант красного курсора редактирования для сравнения.

- Тёмный: пустой слот; зелёный: есть нота. Яркость может передавать velocity.
- Красный: играющая позиция. Разная яркость красного различает пустой/заполненный слот; на LCD остаётся отдельная отметка наличия ноты.
- Янтарный: выбранный шаг для правки. Одновременный красный имеет приоритет на физическом RGB, выбранный шаг остаётся отмечен на LCD.
- Бирюзовый: несколько нот в одном слоте; подробный выбор через Events.
- При Shift пэды временно показывают звуки банка: назначенные бирюзовые, выбранный янтарный, пустые тусклые. Пустой звук можно выбрать и запрограммировать заранее.
- Вне длины секвенции пэды последней страницы выключены и не редактируют данные.

Порядок — штатные номера физических пэдов: снизу1–4, выше5–8,9–12, сверху13–16. Шаг1 не переносится в левый верхний угол. Страница2 использует те же пэды для шагов17–32.

В Steps никакие Shift+Pad меню, запуск другой секвенции, живой Note On или полифоническое давление не должны доходить до обычного обработчика. Изменение REC не должно создавать вторую ноту поверх программирования. Отдельно определить передачу управления Mute/Chop/16 Levels: предлагается явный выход из Steps в соответствующий штатный режим, с видимой сменой экрана, вместо скрытого перехвата пэдов.

## LCD и страницы

Чёрный фон и верхние кнопки стиля r12b. Всегда видны номер секвенции, выбранный звук/банк, размер, Grid, страница/общее число, музыкальная позиция и Follow/Hold. Два варианта макета:

1. **Пэды на экране:** сетка4×4 повторяет физические пэды; справа выбранная позиция, страница и длительность ноты. Предпочтителен для начала.
2. **Лента шагов:**16 позиций слева направо с небольшими столбиками velocity; лучше виден ход времени, но физическая раскладка читается менее прямо.

При4/4 и1/16 страница — один такт. При3/4,5/4,триолях это уже неверно: страницы содержат16 последовательных слотов и могут пересекать границу такта. Показывать страницы и такты раздельно, не менять размер проекта для удобства рисунка.

Follow следует за играющей страницей. +/− или ручной выбор энкодером переводят в Hold без таймера возврата. Shift+B2 явно возвращает Follow. Если воспроизведение ушло на другую страницу, LCD показывает его глобальную позицию/страницу. Ручная навигация редактора не должна перескакивать реальное воспроизведение.

## Copy / Paste в Events

Copy берёт одну выбранную ноту, а не весь шаг/сэмпл/такт. Буфер хранит звук, velocity, длительность, относительный pitch и микросмещение. Paste ставит копию на выбранную позицию и выбирает новый объект; исходник остаётся на месте. Copy не меняет проект.

- **Paste [A03]** сохраняет исходный звук; в меню он указан явно.
- **Paste to Pad [B05]** переносит свойства ноты на явно выбранный текущий звук.
- Уже существующие события не заменяются автоматически. Полностью идентичный дубль в той же позиции пропускается с сообщением; остальные совпадения сохраняются как несколько событий.
- Буфер пуст/событие не выбрано — недоступная команда, без побочного изменения.
- Вставка за концом секвенции запрещена, без скрытого удлинения.
- Каждая вставка/удаление — одна штатная Undo-операция, с dirty flag и штатным сохранением XPJ.
- При смене проекта буфер очищается, чтобы ID звука не ссылался на другую раскладку. Внутри проекта копирование между секвенциями допустимо.

## Что особенно важно не потерять

- Несколько событий, roll/chop и разные высоты одного пэда не сводятся к одному биту. Бит/цвет — только представление списка.
- Существующие ноты между линиями сетки сохраняют точное время. Нажатие/смена Grid не должны превращать их в квантованные ноты без отдельной команды.
- Для первой реализации удаление повторным нажатием пэда разрешить только для одной обычной ноты точно на сетке. Сложный или смещённый слот сначала выбирается; явное удаление одной ноты доступно в Events.
- У Note On и Loop важна длительность ноты. Новые ноты получают один шаг по умолчанию; Note Length редактируется явно. Один и тот же MIDI-note не гарантирует одинакового акустического результата у One Shot/Note On/Loop.
- Счётчик шагов и страниц пересчитывается при изменении Length/размера. Текущая страница корректно ограничивается, хвост не дописывается.
- Команда пэда привязана к странице/звуку/сетке в момент нажатия: Follow, отпускание Shift или уход в другое окно не должны перенести её на другое место.
- Отпускание ранее звучавшего пэда пропускается своему прежнему владельцу, даже если пользователь уже вошёл в Steps; отпускание шагового пэда после выхода не должно попадать в живой движок.
- RGB бегунка берётся от штатной транспортной позиции. Перерисовка LCD и очередь команд не являются музыкальными часами. UI-код не выполняется в аудиопотоке.
- Использовать штатные команды изменения событий и SafeLifetime; не записывать прямо в вектор нот и не перепаковывать XPJ вручную.

## Предлагаемый порядок реализации

**СборкаA:** операции выбранной ноты Copy/Paste/Undo, переходы по тактам и сохранение/повторное открытие из штатного приложения. Это даёт один безопасный путь изменения данных для обоих видов.

**СборкаB:** Steps, RGB/курсор, выбор звука, страницы, включение/выключение нот и velocity через тот же путь. Затем расширение Grid, сложные длительности и несколько событий на слот без упрощения исходных данных.

Это две предлагаемые функциональные сборки, не обещание заранее известного числа отладочных итераций.

## Уточнения r13b после пробы

Актуальное управление описано в PAD_STEPS_RU.md: B1+пэд выбирает звук, Shift+пэд сохраняет штатные меню; обычный пэд добавляет/выбирает, Erase+пэд удаляет. Время идёт13..16→9..12→5..8→1..4; на LCD сетки нет. Энкодер только шаги; K3 сплошная шкала. Generic выход по другим кнопкам убран; B2 переключает Events/Steps. Эти уточнения заменяют противоречащие им ранние предложения выше.


## Актуальное уточнение r13d

Управление и проверка: sd-mod-session/PAD_STEPS_RU.md. Write через локальный SEQ REC; банк листается без смены звука; Erase в Steps удаляет группу одного шага, в Events одиночная кнопка удаляет строку при отпускании, сочетание с пэдом сохраняет штатное подтверждение. Вход выбора события через 16 Levels/Chop, B3 Apply, B1 Cancel. Воспроизведение голубое, удаление красное, будущий mute фиолетовый. Согласован следующий этап Mute: короткое нажатие закрепляет режим, удержание временно включает; после пэда отпускание не переключает режим повторно. Нужна проверка native muted и группового Undo перед реализацией.
