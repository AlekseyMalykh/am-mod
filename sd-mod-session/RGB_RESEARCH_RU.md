# Подсветка пэдов: промежуточные результаты статического анализа

Обновление24 октября2026: пользователь подтвердил рабочую телефонную клавиатуру r10a с RGB через общий отправитель0x23b0ec0. Для новой музыкальной подсветки согласована структура Project → Key / Scale и Sample B2 → Tune / Play / Lights. План и ограничения: SIXTEEN_LEVELS_LIGHTS_RU.md. Ниже сохранены ранние результаты исследования; старые формулировки «RGB не проверен» относятся к моменту их получения, а не к последующей пробе клавиатуры.

MPC Sample1.3.0.12, SHA приложения закреплён в build-info.json. Сборка r9a не включает изменения RGB/раскладки. Анализ был прерван разбором отказа r9; результаты не являются физической проверкой LED.

## Найденный путь цвета

- PadLightingChain: RTTI0x49d79e8, primary vptr0x6d8d790. Refresh path0x1535170 обходит цепочку; её остальные вспомогательные пути0x1534a20/0x1535150 требуют дальнейшего сопоставления приоритетов.
- SixteenLevelLighting: RTTI0x49d8348, primary vptr0x6e10a60; обработчик отдельного пэда0x1545930. Читает enabled bit по properties+0x2f8 и type+0x88, использует разные исходные цвета для type0/1/2. Индекс localPad=pad&15 и яркостный коэффициент localPad/16; colour scaler0x1a4c9d0 масштабирует три 8-битных канала.
- Вывод PadLight через0x1a3ffb0: младшие32бита цвета и float параметр в старших32 переданного x2 (обычно1.0f). Полную семантику второго поля нужно уточнить по анимации; не считать его RGB alpha без исследования.
- AC50MidiSender constructor0x159ff70, initialize0x15a0410. Регистрирует16 callback с индексами0..15 на0x159f910; callback принимает PadLight и индекс, вызывает converter0x23b00c0 и sender0x23b0ec0.
- converter0x23b00c0 читает uint32 colour и float+4; Для положительного множителя выше малого epsilon применяется минимум0.02; в этой функции верхнего ограничения1.0 не найдено. Нулевой множитель даёт выключенное состояние, достаточно отрицательный переводится в0.02. RGB умножается на него перед отправкой.
- packer0x23b0070 формирует12байт: F0 47 7F <sender-device-id> 65 00 04 <pad-index> <R>>1 <G>>1 <B>>1 F7. Каждый канал берётся 7битами из 8-битного RGB. Упакованный цвет RRGGBB; не фиксированная палитра. Сам sender берёт device-id из собственного byte+0x80; значение для физического AC50 ещё не установлено.
- Статически это подтверждает независимый цвет16пэдов и7бит/канал в протоколе. Реальная яркость/гамма, любые выбранные оттенки, соответствие физической нумерации и поведение при конкурирующих режимах ещё не проверены. Общие имена PadColorGroupMap из MPC-кода сами по себе не использовались как доказательство.

## Tune и будущие функции

Штатное руководство: original pitch на физическом Pad4; ниже/выше — понижение/повышение. В SixteenLevels processor0x21472f0 type1 использует локальный индекс pad modulo16 минус поле originalPad+0x228 и передаёт смещение в0x27e4400. Вызов идёт из note-on path0x1e27360→0x21472f0, release из0x1545050 отдельно. Точные enum имена, шаг высоты и ограничение режимом AC50 ещё требуют сопоставления; подсветка и перестановка нот — разные изменения.

Для телефонного ввода нужна временная приоритетная LED-раскладка только в редакторе имени с Pads, совместно с перехватом нажатия/отпускания/давления до музыкальных обработчиков. Один цвет не подавляет звук. При выходе должен выполняться штатный Refresh, иначе новый слой будут перезаписывать playback/mute/Shift.

Для Tune сначала можно добавить цветовую разметку существующих интервалов, затем отдельно меню root/layout/scale и отображение нот. Нельзя называть исходный строй сэмпла C без заданной root note или анализа высоты. Палитра и геометрия раскладки пока не утверждены.

Источник поведения16Levels: https://www.akaipro.com/guides/mpc-sample/pad_play.htm . Анализ исходного ELF выполнен чтением/дизассемблированием, без отправки MIDI на устройство и без runtime тестов.
