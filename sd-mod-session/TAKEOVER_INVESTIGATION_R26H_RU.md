# Повторная проверка r26h: общий сбой K, Trim End 100 → 0 → 91

Аппаратное сообщение: r26h не устранила застревание; пользователь уточнил,
что оно затрагивает все параметры K, а Trim K2 End — конкретный пример.
OptoCat из 81189e0 остаётся частью мода.

## Подтверждено

- На физической карте установлена библиотека r26h с ожидаемой контрольной
  суммой; в отчёте запуска есть `SCALED_ENDPOINTS_INSTALLED`.
- Отчёт карты снимался при запуске, до движений K. В нём нет RAW/EDGE
  пользовательского воспроизведения. Нужен выход через Project → Mod Off
  после сбоя, чтобы выгрузить текущий RAM-журнал.
- Живой ARM-эмулятор с библиотекой r26h: аппаратный K2 на Trim приходит в
  `TrimParameter`, vptr `0x6e1b240`, callback `0x15e9260`, core `0x15e70c0`.
  Поля: slider `+0x70`, mode `+0x134`, active `+0xf3`, history `+0x19c/+0x1a0`.
- При переходе на Tune K1/K2 используют RotaryFixedConnection с callback
  `0x15f5690`; K3 также использует этот callback. Это именно тот класс,
  который проверяли изолированные тесты r26g/r26h. Он не покрывает Trim.
- Следовательно, r26h не корректирует TrimParameter. Прохождение прежних
  тестов не является проверкой аппаратного маршрута Trim End.

## Сравнения только в отдельной виртуальной машине

При быстрых пакетах по 128 положений получались промежуточные показания End,
включая 93/97, при history = 1/1 и промежуточной реальной границе сэмпла.
Это наблюдалось также при временном восстановлении исходного native callback
ввода и при временном восстановлении штатных Slider/Label painters.
Исходники и физическая карта этими RAM-сравнениями не менялись.

Трассировка показывает запись границы из Trim core через `0x14d0890`
(caller `0x15e7d68`), а затем подтверждение со стороны движка
(caller `0x228e798`). В частности, после запроса 4410 приходили подтверждения
44 и 4409. После тихого интервала граница достигала 4409 и показывала 100%.
Одиночные переключения между 0 и 127 с паузой дали 0/100 в обе стороны.

Поэтому промежуточный результат под нагрузкой эмулятора ещё не доказывает
причину устойчивого аппаратного застревания. Отключение очереди или painter
нельзя считать подтверждённым исправлением. Прямое изменение истории Trim
также не обосновано наблюдением: рассчитанный Scaled результат уже достигал 1.

## Что нужно уточнить на устройстве

1. Сохраняется ли 91 через 10–15 секунд после остановки ручки.
2. Присутствует ли точное RAW 127/0 в воспроизведении.
3. После воспроизведения: Project → Mod Off, затем вернуть карту в ПК и
   сохранить полный журнал. Не перезапускать мод перед чтением журнала.

Неподтверждённый вариант прямой доставки native K сохранён отдельно в локальных
ветках/стэшах исследования; в пакет и на карту не включён. Правка второго
математического обработчика также не включена. До аппаратной диагностики
новый релиз и закрытие обращения #2 не подготовлены.
