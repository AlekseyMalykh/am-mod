Seq передаёт запрос хозяину штатного режима, Sample сначала готовит источник, затем предлагает FX и Render. Сам выбор Sample не меняет проект.

По новому решению пользователя предел цепочки — **пять эффектов**, включая EQ; Bypass занимает слот. В списке K1 выбирает слот, B2 переключает Bypass, B3 запрашивает редактор/выбор эффекта. **Shift + B2 / Shift + B3** перемещают выбранный эффект выше/ниже, без закольцовывания. Настройки, все16 параметров и Bypass перемещаются вместе; курсор следует за эффектом. DSP обрабатывает список сверху вниз. Число полос внутри EQ осталось прежним — четыре.

## Экран и время жизни задания

- `src/resample_flow.c/.h`: страницы выбора, подготовки, настроек, FX, рендера, готового результата, подтверждения занятой цели, переключения сравнения, Apply и отмены. Кнопки учитываются по обеим границам нажатия; удержание B3 не подтверждает замену. Play/Stop остаются штатными. Native маршрутизация этих событий пока не подключена.
- `src/resample_view.c/.h`: чёрный320×240, пять строк FX, отдельные группы источника, прогресса и назначения; K1–K3 по центру. Макеты в `work/resample/` получены из вызовов настоящего painter, а не снимков MPC.
- `src/resample_worker.c/.h`: UI передаёт копии команд через ограниченную очередь16; существующий будущий worker выполняет не более4096 кадров за шаг. Новых потоков модуль не создаёт. Подготовленный источник, готовый PCM и временная подстановка имеют явное владение. При отмене результат освобождается только после подтверждения возврата Original.
- Сравнение и Apply принимают от native адаптера Done/Pending/Failed. Pending не считается успешным Apply; результат остаётся жив, пока задача native очереди может его читать. Отмена, stale token и отказ восстановления проверены отдельно. Отсутствие Apply/Undo адаптера даёт явную ошибку. Занятая цель требует отдельного подтверждения; реальный адаптер обязан повторно проверить проект, источник и цель.
- `src/pad_output_stream.cc/.h` + `src/pad_output_abi.S`: результат рендера представлен как owned native ProcessingStream, без второй полной PCM-копии. Источник удерживается retain/release. На ARM исполняются реальные native metadata/EOF/seek и Trim-consumer; совпадают кадры, Stereo и владение после отпускания владельца. Это ещё не регистрация нового Sample в проекте.
- Текущий источник — сырой PCM слоя0 с Trim. Tune/огибающая/фильтр/кривая velocity ещё не запекаются. Пока backend не подтверждает поддержку velocity, K3 Velocity скрыт; запрос неподдерживаемого значения отклоняется явно.

Проверки `verify_resample_flow.py`: обычные ARM и UBSan варианты контроллера/worker,50 конкурентных сеансов UI/worker, отложенные native подтверждения, отмена/ошибки, реальный поток готового результата. `verify_fx.py` дополнен аудиотестом пяти некоммутирующих стадий: перенос усиления после ограничения меняет PCM. Здесь используются обозначенные тестовые backend-эффекты, это не подтверждение современных native FX.

**К установке на устройство этот прототип ещё не готов.** Требуются native вход/экран/lifecycle, действительная рабочая очередь устройства, обработка пэда и современные FX, подстановка в микс и Apply/Undo/Save. `phone_build.py`, autorun, архив и SD с r16d не изменены. Отчёт нового этапа: `build/resample-flow/verification.json`.

## Новый этап: native Sample → ограниченный захват → FX

- `src/pad_sample_source.cc` берёт сэмпл слоя0 выбранного пэда0..127 через настоящие Program/layer getters. Границы Trim копируются до запуска; Program и слой после открытия не удерживаются. Native Sample и отдельный поток чтения остаются во владении захвата, поэтому последующая смена назначения пэда не подменяет исходник задания. Получение снимка выполняется владельцем модели при стабильных параметрах.
- Native Sample создаёт поток через штатный getter; результат с C++ ABI x8 и собственной функцией удаления не подменяется сырым указателем. Чтение передаёт число кадров и получает полный owned block с completion, затем EOF/seek; освобождаются блок, поток и отдельная сильная ссылка на Sample. Прежнее описание «span» исправлено после настоящего MemorySample reader.
- `pad_render_create_stream` не создаёт промежуточную полную PCM-копию. Он читает прямо в уже учтённый буфер исходника, максимум256 кадров за чтение. Захват и рендер вместе расходуют максимум4096 кадров за шаг; прогресс отдельно показывает `source_done/source_total` и `done/total` обработки. Существующий API готового PCM сохраняет немедленный независимый снимок.
- Native поток закрывается сразу после захвата, при отмене, ошибке или уничтожении задания. Неудачная подготовка задания не отбирает владение потоком у вызывающего кода. Неполный/нечисловой вход не выдаёт готовый результат.
- В pinned metadata `uint16+0` — каналы, `int+4` — кадры, `int+8` — частота дискретизации. `float+0x3d0` — BPM исходника, с диапазоном20..999. Проверено независимое значение91BPM при48000Гц, а также mono44100Гц. Старые PCM/Extract fixture-проверки исправлены, чтобы не называть поле частоты числом каналов.

Native карта источника:

| Участок | Адрес/поле | Проверенная роль |
|---|---|---|
| Program → instrument | `286bbe0` | Индекс пэда, включая другой банк |
| instrument → layer0 Sample | `2803b90`, результат x8 | Отдельное владение Sample; связь instrument+2310 с Program проверяется |
| Trim слоя0 | layer+740, вложенные +78/+d0 | Копия начала и исключающего конца без изменения слоя |
| Sample → read stream | `2943250`, результат x8 | Снимок native provider и возврат owned reader |
| Чтение/EOF/seek | `20c5f60` / `20c58f0` / `20c5f30` | Span одного кадра, границы и сброс EOF при перемещении |
| Удаление reader | Собственная функция из результата getter | Native время жизни потока, затем освобождение удержанного Sample |

В ARM/QEMU исполняются эти getters и методы; provider/декодер исходного PCM в тесте детерминированный. Проверены mono/stereo, Trim, повтор/хвост, другой банк, независимость от последующих изменений слоя, совпадение результата native-источника → EQ с обработкой того же готового PCM, Cancel и ошибочные пути. Это ещё не проверка декодирования реального файла на устройстве и не захват живого звучания пэда. Pitch, огибающая, фильтр, многослойный микс и обычные FX пэда этим источником не запекаются.

## Что реализовано

`src/pad_render.c` — отдельная подготовка обработанного аудио в памяти:

- При создании задания снимается независимая копия выбранного участка исходного PCM. Mono приводится к stereo; частота дискретизации сохраняется. Изменение исходного буфера после создания задания не влияет на результат.
- Последовательная цепочка до **пяти FX**, включая EQ. Используется существующий fx_chain; каждый рендер получает новые экземпляры и пустую историю обработки. Предыдущий обработанный результат не становится новым источником автоматически.
- Явное конечное повторение участка 1–64 раза для будущего Loop-сценария, затем заданный хвост: в FX поступают нули, а не новые запуски сэмпла. Настройки Loop исходного звука не меняются.
- Работа порциями до4096 кадров за один вызов, DSP-блоками до256 кадров. Есть прогресс и запрос отмены между блоками. Новые потоки не создаются; будущий адаптер должен вызывать обработку на управляющей рабочей очереди, не в реальном аудиоколбэке MPC.
- Создание, обработка, чтение прогресса/результата и освобождение принадлежат одному владельцу. Из другого потока разрешён только атомарный запрос отмены. Для UI и live-аудио ещё нужен отдельный проверенный мост передачи состояния и времени жизни результата.
- Лимит **64MiB на сумму копии источника и выходного stereo PCM**; можно задать меньший бюджет. Проверяются переполнение счётчиков, границы участка, число повторов и FX до начала обработки. Внутренняя память стороннего DSP в этот PCM-бюджет не входит: её нагрузку ещё требуется измерить отдельно.
- Ошибка подготовки FX, NaN/Inf на входе/выходе или отмена не дают доступ к незавершённому результату. Собственные буферы и FX освобождаются. До DONE получить выходное аудио нельзя.
- Peak и число кадров выше0dBFS сообщаются явно; скрытой нормализации или изменения исходника нет.

Черновик FX расширен с12 до **16 параметров на слот**: штатные описания AC50 используют индексы12/13 для фильтра, реверберации и компрессора; зарегистрированный четырёхполосный EQ использует14. Эти значения нельзя терять при копировании настроек. Это изменение пока только независимого FX core, не производственной библиотеки мода.

## Выполненные проверки

`verify_pad_render.py` компилирует ARM-исполняемые тесты и запускает их в QEMU с закреплённым rootfs. Отдельно выполняется тот же core с UndefinedBehaviorSanitizer.

Проверены точная обрезка/повтор/длина хвоста, независимость источника и размера блоков, новый рендер от исходника, Bypass, конечность вычислений, границы памяти, отмена до и во время обработки, очистка частично созданной цепочки, запрет выдачи незавершённого результата и headroom без автоматической нормализации.

`check_pad_render_native.c` исполняет **реальную старую фабрику EQ81 из прошивки**, её prepare, параметры, stereo process и destroy внутри нового рендера, последовательно с нашим четырёхполосным EQ. Проверены воспроизводимость нового рендера и пять занятых Bypass-слотов без запуска DSP. Аудиоданные тестовые; это не запись с MPC. Старый EQ81 не является новым пунктом FX Select и не подтверждает подключение современных штатных FX.

Дополнительно выполнен `verify_fx.py`: аудиотесты EQ, лимит/порядок/очистка цепочки, конкурентная смена обработчиков и native-каталог. Проверки индексов13–15 включены в валидацию черновика.

Отчёт: `build/resample/verification.json`. Он проверяет и сохраняет контрольные суммы производственных файлов r16d до/после проверки. Верификатор не обращается к SD и не вызывает build.py. Обычный и UBSan-варианты отдельно проверяют новый порционный захват.

## Следующее подключение

1. Связать готовый адаптер слоя0 с владельцем модели/рабочей очередью и подтвердить его на настоящем Sample устройства. Отдельно подключить Tune/огибающую/фильтр выбранного звука, без остальных партий и без запекания Volume/Pan/Kit/Master FX. Текущий прототип захватывает Trim исходного PCM и обрабатывает FX; высоту и огибающую пэда он пока не запекает.
2. Подключить современные штатные FX к независимым экземплярам цепочки. Проверить порядок, параметры, время жизни и ресурсный отказ. Пять слотов — предел проекта, не обещание любой комбинации на железе.
3. Сделать Original / FX Preview / Rendered в играющем миксе: один источник события, без двойного звука и новых записанных нот. После изменения черновика старый Rendered становится устаревшим.
4. Отложенное Apply: Replace / To Pad, подтверждение занятой цели, сохранение остальных пэдов с общим исходным сэмплом. Обойти только уже запечённые стадии; объединить назначение и сброс этих стадий в один Undo.
5. Подключить экран, прогресс, Cancel/смену проекта/Mod Off, External Save и повторное открытие. После локальных проверок подготовить отдельную аппаратную пробу; текущая r16d на карте остаётся рабочей версией без этого прототипа.

Текущий результат — рабочий локальный аудиорендер и аудит штатных точек, **не готовая функция меню MPC**. Полные требования остаются в PAD_RESAMPLE_DESIGN_RU.md и PARAMETRIC_EQ_DESIGN_RU.md.
