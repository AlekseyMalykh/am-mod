# Проверка коротких нот у границы секвенции

Проверяется сообщение пользователя о нестабильной длине записанных событий обычного Sample Note On и Tune / 16 Levels. На этом этапе причина на физическом MPC не установлена и исправление не заявляется.

## Стенд и метод

Полный системный QEMU, native ELF 1.3.0 и проверенная trial-библиотека `b20b44f7422d2a8fa4e6c0c5f791a8f6a709e4a35e33c759aea4d3bce1fc517d`, ветка `codex/pad-midi-recording`. Двухтактовый loop 4/4, длина 7680 ticks, темп 128. В A01 штатным браузером загружен сгенерированный четырёхсекундный mono WAV (44.1 kHz, 220 Hz, int16, амплитуда 6000). Shift+Chop включает native Note On: белая нотная пиктограмма на Sample, `triggerMode=2` в XPJ. Synth trial для этих тестов не включён.

`lab/watch_native_clock.c` читает только опубликованный `clock_tick` через `/proc/PID/mem`, не меняет память и не создаёт музыкальные события. Адрес берётся из symbols точной проверенной библиотеки и её реального mapping. `lab/check_note_on_boundaries_vm.py` ожидает нужную позицию, отправляет обычные control-surface Down / Up, останавливает transport и читает штатный autosave XPJ. Для Tune используется физический Pad 5; сохранённые события имеют активный native Tune modifier. Record Quantize переключается штатным Shift+Pad 10; его фактическое состояние берётся из XPJ **после** прогона, поскольку начальный autosave может ещё отражать предыдущее состояние UI.

В TCG настенное время удержания и музыкальное время могут сильно отличаться. Поэтому длительность оценивается по native clock около Down / Up, с допуском на обновление UI-позиции и обработку surface пакета. Первый пробный отчёт `note-on-end-quantized-verification.json` сравнивал с настенным временем и ошибочно помечал 351 ticks как подозрительно короткие; такой метод помечен недействительным и не является воспроизведением бага. Его фактический quantize также был Off. Ниже приведены только последующие проверки с native clock trace.

## Полученные результаты

| Ввод | Record Quantize | Clock перед Down | Удержание по native clock | Начало в XPJ | Длительность в XPJ |
|---|---|---:|---:|---:|---:|
| Sample Note On | Off | 7591 | 672 | 7603 | 672 |
| Sample Note On | On | 7597 | 606 | 0 | 582 |
| Tune / 16 Levels | On | 7597 | 618 | 0 | 606 |
| Tune / 16 Levels | Off | 7585 | 624 | 7592 | 630 |
| Tune, короткий Down/Up | On | 7603 | 36 | 0 | 60 |
| Sample, короткий Down/Up | On | 7602 | 36 | 0 | 72 |
| Tune, Down за 12 ticks до границы | On | 7668 | 565 | 0 | 582 |
| Sample, Down за 12 ticks до границы | On | 7668 | 595 | 0 | 642 |

Удерживаемые ноты продолжаются через границу loop; у неквантованных событий длительность выходит за конец размещения секвенции. При quantize начало может оказаться на tick 0 следующего прохода, сохраняя ненулевую длительность удержания. Превращение длинного удержания в минимальный gate в этих прогонах не воспроизвелось. Короткие 60/72 ticks получены при намеренно коротком нажатии около 0.046 секунды настенного времени, а не при длинном удержании. Это не доказывает причину наблюдения пользователя.

В исследованном native finalizer `0x213b130` длительность вычисляется по внутреннему timestamp начала pending note (`node+0x58`); при нулевой разнице применяется штатный минимум 60 ticks. Само наличие этой ветки не доказывает ошибку quantize или зацикливания. Расчёт длительности native recorder в рамках этой проверки не изменён.

## Артефакты и повторение

В `build/pad-midi-pads` для каждого валидного case хранятся `*-clock.json`, `*-verification.json`, XPJ до/после и расшифрованный native JSON. Отчёт содержит фактический quantiser, clock, события, SHA-256 библиотеки/XPJ и `hardware_tested=false`. Сгенерированные образцы, образы дисков и проекты не входят в Git.

```sh
aarch64-linux-gnu-gcc -O2 -Wall -Wextra -Werror \
  lab/watch_native_clock.c -o build/pad-midi-pads/watch-native-clock
AM_MOD_VM_RUN_NAME=pad-midi-recording-pads \
  python3 lab/check_note_on_boundaries_vm.py note-on-end-free --velocity 63
```

Перед прогоном следует явно установить нужные Note On / 16 Levels / Record Quantize через native UI. Для самого конца цикла применяется `--before-end 24`; для короткого удержания `--hold .04`. Clock фиксируется перед отправкой пакета; это не точное измерение момента принятия On аудиопотоком. Для каждого take нужна отдельная velocity, чтобы отличать событие от предыдущих записей. Скрипт предназначен только для этого частного QEMU-стенда.

Остаётся аппаратная проверка на проекте, где возникала проблема, включая его tempo/grid, Note Repeat, состояние loop и нагрузку FX. Записанная длительность и преждевременное завершение слышимого sample — разные симптомы; текущий набор проверяет прежде всего события XPJ.
