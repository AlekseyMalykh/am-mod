# Следующий workflow: секвенция как блок с несколькими строками событий

Предложение пользователя после прямого New/Open/Edit. Отделение/копирование
строк уже подключено: [ARRANGE_SEPARATE_ROWS_RU.md](ARRANGE_SEPARATE_ROWS_RU.md).
Ниже исходный план; групповые Move/Chop/Merge ещё не реализованы.

## Представление

Штатная Sequence остаётся исходным материалом. В Arrange её скопированные
события могут находиться в одном Pattern: Drums + Bass + Samples. Такой
Pattern уже допускается текущей моделью — у него несколько Route и событий.
Снаружи это один блок, внутри — строки пэдов в существующем Piano Roll.
Назначения на Mixer A–H не определяют музыкальную структуру.

Основной жест остаётся B3 Open. Внутри пользователь выбирает строки, а не
обязан предварительно записывать каждый инструмент в отдельную Sequence.
Первый вариант выделения нескольких строк следует подключить к существующему
Pad/Tune/Chop редактору и его диапазонам, без второго редактора. Постоянное
раскрытие вложенных строк прямо на timeline можно добавить позже; экран
320×240 должен сохранять быстрый возврат к свёрнутым музыкальным блокам.

## Отделить строки

Пример: исходный блок содержит A1 Kick, A2 Snare, A3 Hat, B1 Bass, C1 Vocal.
Выделить A1–A3 → Separate rows → появляется блок Drums на самостоятельной
музыкальной дорожке с той же начальной позицией, длиной и source phase.
В оставшемся экземпляре блока находятся Bass и Vocal. Они не играют второй
раз вместе с уже отделёнными Drums.

Исходная штатная Sequence и исходный Pattern в библиотеке не меняются.
Операция создаёт два новых материала: выбранные события и остаток, и заменяет
ссылку только текущего блока на остаток. Остальные экземпляры исходного
Pattern сохраняют прежний материал. Всё действие — одна транзакция Undo.
Если отделены все строки, пустой остаток не создаётся; текущий экземпляр
переносится на новую дорожку со ссылкой на самостоятельный Pattern.
Copy rows — отдельное явное действие, сохраняющее
и полный текущий блок, и копию выбранных строк.

При разделении нужно сохранить period исходного Pattern, native gate,
clip.start/length/offset, mute и происхождение событий. Нельзя сокращать
новую партию до последней найденной ноты: иначе повторения начнут расходиться.
Текущие 32 pattern / 32768 events — действующие ограничения; создание двух
копий заранее проверяет бюджет и при отказе сохраняет весь прежний Store.

Идентификатор строки — не один номер пэда: важны Program и слой события.
Если одним пэдом сыграны несколько партий в Tune/16 Levels, ручное выделение
нот/диапазона должно позволять отделить их независимо. Автоматический Split
by Pads или Mixer остаётся начальным удобным вариантом.

## Переместить, разрезать, объединить

Один блок с несколькими строками перемещается целиком. Выделенная группа
блоков перемещается/меняет дорожки с сохранением относительных координат;
нужно проверять коллизии по итоговому состоянию всех блоков, а не применять
перемещения по одному. Preview/Apply/Cancel и Undo остаются общими.

Chop на курсоре должен разрезать все выбранные блоки, внутри которых есть
курсор, одной транзакцией. Сохраняются длина левой+правой частей и phase;
границы блоков не обрезают удерживаемые ноты автоматически. Перенос правого
куска длинного sample-trigger не превращает его в воспроизведение аудио с
середины: для этого позже нужен audio/render backend.

Group — обратимое объединение размещений для совместных операций, без
копирования нот. Для первого этапа достаточно временного multi-selection;
постоянные группы требуют отдельной версии необязательных метаданных.
Merge events — другое действие: создаётся новый редактируемый Pattern с
событиями всех выбранных блоков, корректно развёрнутыми repeat/offset и
перенесёнными относительно общей начальной позиции. Исходники сохраняются.
Join соседних кусков того же Pattern остаётся прежней простой операцией.

## Порядок подключения

1. Довести выделение нескольких строк/событий в существующем Pattern host.
2. Добавить атомарный Separate rows / Copy rows с готовыми библиотечными
   Pattern IDs и наследованием длины, маршрутов и фазы.
3. Подключить multi-selection блоков и групповые Move/Chop/Undo.
4. Добавить Merge events с ограничениями ресурсов и детерминированным
   порядком одинаковых onsets.
5. Решать постоянные группы/inline expansion после проверки на устройстве.

Новые операции не открывают непроверенный native source reader, не запускают
несколько штатных Sequence и не меняют формат штатного проекта. Развитие
Arrange playback/record и реальное удержание native объектов остаются
отдельной необходимой частью интеграции.
