# Запуск копии MPC Sample через SD

Проверено 22 октября 2026 года. Исследование, не готовая инструкция запуска. На SD и устройство ничего не записано.

## Что сообщил автор SXL

Источник: https://www.mpc-forums.com/viewtopic.php?f=50&t=221007

Автор vinylstyle ссылается на то же видео yLyX3jAosX4. 14 октября он описал изменённый ARM64-бинарник MPC поверх штатной 1.3.0.12 и запуск через SD autorun в отдельном Linux mount namespace. 18 октября уточнил порядок: штатная загрузка, ожидание её завершения, остановка штатного процесса, запуск изменённого приложения. Готового загрузчика SXL в проверенных источниках не найдено.

SD autorun у нас уже работает. Веб-загрузка /testapp не является необходимым звеном описанного пути. Следующая цель — передача управления побайтово неизменённой копии приложения и проверка возврата; функциональные патчи следуют после проверки загрузчика.

## Наша схема для дальнейшей разработки, ещё не проверенная на устройстве

1. Проверить бинарник и подготовить исполняемую копию в проверенной RAM-файловой системе.
2. До остановки штатного приложения подготовить отдельный механизм возврата, переживающий сбой копии и её загрузчика.
3. Управляемо остановить ac50.service и подтвердить освобождение ресурсов.
4. Создать отдельное пространство монтирования, отключить распространение монтирований наружу и запустить копию с проверенным окружением и путями.
5. После завершения/сбоя копии вернуть штатное приложение вне временного пространства. Для зависания нужен отдельный контроль времени и завершения.

Это инженерная схема, не найденные команды автора. Вызов systemctl внутри namespace сам по себе не помещает запускаемую системным manager службу в этот namespace.

## Локальные факты и ограничения

- sd-runtime-inventory/MPC_SAMPLE_RUNTIME.txt подтверждает Restart=always у ac50.service и одновременную работу autorun через отдельный az01-script-runner. Простое убийство PID может вызвать конкурирующий запуск штатного экземпляра.
- launch-ac50 вызывает az0x-firmware-tool до запуска MPC. Его нельзя считать нейтральной командой запуска копии. Возврат через штатную службу также использует этот wrapper; это нужно учитывать отдельно.
- /run в отчёте — tmpfs, корень — ext4 ro, SD — exfat noexec. Доступность механизма namespace и выполнение будущей копии ещё не проверены.
- Namespace изолирует таблицу монтирований, но сам по себе не запрещает запись в общие файлы, /data или доступные устройства. Для сохранности проектов нужно отдельно учитывать автосохранение и пути записи копии. Нулевой риск из этого механизма не следует.

Семантика namespace: https://man7.org/linux/man-pages/man7/mount_namespaces.7.html

## Сторонний код

https://github.com/gospodindilly-ops/mpc-sample-patcher

Это проект другого участника, не опубликованный SXL. README отмечает отсутствие аппаратного тестирования. Прочитаны apply.sh, rollback.sh и scripts/autorun; код не выполнялся.

В apply.sh нет создания отдельного mount namespace: bind-mount выполняется в текущем пространстве. Файл .pending удаляется до перезапуска приложения, поэтому он не защищает от последующего цикла падений. При ошибке перезапуска автоматического снятия подмены нет. Входной scripts/autorun не содержит проверенного у нас комплекта autorun.json/autorun.check. Пакет требует переработки перед испытаниями.

Нет точного скрипта SXL, карты его подменяемых путей, окружения и механизма возврата. Способ внесения функциональных изменений также неизвестен. MPC XL автор использовал как референс; это не доказывает необходимость XL для запуска копии на Sample.

## Подготовленный локальный прототип

Создан собственный пакет `sd-clone-trial/` и архив `mpc-sample-unmodified-clone-trial.zip`. Он использует отдельные службы systemd в RAM, предварительную проверку ограничений, 30-секундный предел копии и независимый таймер возврата на 75 секунд. При возврате оригинал запускается через временную настройку службы напрямую, без вызова firmware-tool. Настройка исчезает после перезагрузки.

Семь сценариев на systemd 255 в WSL проверяют управление процессами на тестовом ELF, включая падение supervisor, отдельный таймер и отказ записи в тестовый файл на постоянном диске. Они не доказывают работу MPC GUI/аудио. Синтаксис проверен ARM64 BusyBox из прошивки через QEMU. Инструкция и ограничения — в `sd-clone-trial/README_RU.md`; результаты — `sd-clone-trial/test-results.json`. Аппаратное испытание пока не выполнено.
