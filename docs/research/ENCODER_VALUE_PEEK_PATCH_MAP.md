# MPC Sample 1.3.0: карта изменения «показ значения K-параметра»

Дата аудита: 2026-08-08.

## Вывод

Для этой функции не требуется менять обработку `Shift`, направление обхода
K1/K2/K3, аудиодвижок, параметры сэмпла или формат проекта. Штатная прошивка
уже умеет выбирать следующий параметр нажатием энкодера и предыдущий через
`Shift + энкодер`, а существующий `ui::ValueLabel` уже выдаёт отформатированное
значение параметра.

Требуемая логика должна быть добавлена в экран Sample после фактической смены
фокуса:

1. Определить, какой из K1/K2/K3 получил фокус.
2. Получить уже отформатированный текст из связанного `ui::ValueLabel`.
3. На 1000 мс заменить нижнюю подпись выбранного K-параметра его значением.
4. Повторное нажатие энкодера или изменение параметра перезапускает таймер.
5. По таймеру вернуть штатное имя параметра и перерисовать только строку K.
6. При уходе с экрана, смене вкладки B или уничтожении экрана отменить таймер,
   чтобы отложенный callback не обращался к старому компоненту.

## Что подтверждено в бинарнике

Исследуемый файл:

- `extracted_v1.3.0/partitions/part3/usr/bin/MPC Sample`
- размер: `119243440` байт;
- SHA-256: `B6584CBA76E416E432AD202509099D34373DC2C3D6A8FB625F5678BF0193B508`;
- ARM64 ELF, монолитное приложение на JUCE, без таблицы локальных символов.

Подтверждённые элементы:

| Элемент | Доказательство | Значение для патча |
|---|---|---|
| `SampleModeScreen` | RTTI-строка `0x04a08088` | Изменение следует ограничить экраном Sample. |
| `SampleModeScreen::SetupRotaryAutoFocus()` | RTTI слушателя `0x04a0d5f8` | В Sample уже есть отдельная логика автофокуса ротари. |
| callback автофокуса | код `0x01654180` | При `bool=true` назначает фокус компоненту экрана. Это кандидат для наблюдения, но ещё не доказано, что именно сюда приходит `cursorCentre`. |
| функция установки фокуса | код `0x015c13c0` | Сравнивает старый и новый компонент и сохраняет новый фокус. Это надёжная точка определения факта смены фокуса, но она глобальная и требует фильтра по `SampleModeScreen`. |
| контейнер фокуса Sample | обращение `screen + 0x99c0` в `0x0165418c..0x01654198` | Подтверждает, что экран хранит отдельный объект аппаратного фокуса. |
| `ui::ValueLabel` | RTTI `0x05d5a9c0`, строка компонента `valueLabel` `0x04617c10` | Форматирование чисел, единиц и текстовых enum следует переиспользовать. |
| `RotaryFixedConnection<ui::ValueLabel>` | RTTI `0x04a10a70`, `0x04a10ac8`, `0x04a10bb8` | Значение уже связано с ротари и обновляется штатным соединением. |
| JUCE `Timer` | RTTI `0x0496dbd0` | Односекундное восстановление можно сделать в UI-потоке штатным таймером. |
| `MessageManager::callAsync` | RTTI `0x0496e088` | Доступна безопасная постановка UI-обновления в очередь, если событие приходит не из UI-потока. |
| `cursorCentre` | строка `0x04599c60`, описание `0x04599c70`, построение таблицы около `0x0140137c` | Нажатие энкодера представлено как центральная кнопка курсора. |
| `ADA2CursorResponder` | RTTI слушателей `0x04a3abd8` и `0x04a3ac38` | Общая навигация курсора отделена от Sample-экрана; глобально менять её не следует. |

Три callback конструктора `SampleModeScreen` по адресам `0x016672c0`,
`0x016673c0` и `0x016674c0` переключают наборы соединений/видимости и вызывают
общий пересчёт `0x01654b30`. Это логика групп B1/B2/B3 и их вкладок, а не три
обработчика физического энкодера. Их нельзя заменять патчем показа значений.

## Предпочтительное изменение при наличии исходников

Добавить в `SampleModeScreen` небольшой контроллер временного отображения:

```cpp
struct ParameterPeekState {
    int focusedK = -1;       // 0..2
    bool valueVisible = false;
    uint32_t generation = 0; // отмена старого timeout
};
```

Псевдологика:

```cpp
void SampleModeScreen::onHardwareFocusChanged(Component* focused) {
    const int k = indexOfCurrentKComponent(focused);
    if (k < 0)
        return;

    peek.focusedK = k;
    peek.valueVisible = true;
    const auto generation = ++peek.generation;
    refreshKFooter();

    Timer::callAfterDelay(1000, [safeThis, generation] {
        if (safeThis && safeThis->peek.generation == generation) {
            safeThis->peek.valueVisible = false;
            safeThis->refreshKFooter();
        }
    });
}
```

Отрисовка нижней строки должна выбирать:

```text
valueVisible && i == focusedK
    ? currentValueLabel[i].getText()
    : currentParameterCaption[i]
```

Важно использовать weak/safe pointer либо отменяемый `Timer`, потому что
экран может быть закрыт раньше окончания секунды.

### События, которые должны запускать peek

- обычное нажатие энкодера после перехода K1 → K2 → K3 → K1;
- `Shift + энкодер` после обратного перехода;
- по желанию — первый тик самого K1/K2/K3, если штатный автофокус уже меняет
  выделение. Это следует подтвердить на устройстве, а не добавлять вслепую.

### События, которые должны завершать или пересобирать peek

- истечение 1000 мс;
- смена вкладки B1/B2/B3: старое значение скрывается, затем можно показать
  значение соответствующего K на новой вкладке только после нового действия;
- выход из Sample;
- удаление/смена выбранного сэмпла, если связанный `ValueLabel` пересоздаётся.

## Вариант бинарного патча без исходников

В текущем ELF нет свободного места внутри callback `0x01654180` для всей
логики: функция занимает несколько ARM64-инструкций. Нужен переход в отдельный
trampoline/модуль, а не серия замен непосредственно на месте.

Предпочтительный порядок:

1. Перехватить завершившуюся смену UI-фокуса около `0x015c13c0`.
2. Немедленно отфильтровать все экраны, кроме активного `SampleModeScreen`.
3. Проверить, что новый компонент входит в текущую тройку K-компонентов.
4. Прочитать текст существующего `ui::ValueLabel`, не вычисляя значение заново.
5. Установить флаг/текст временной подписи и запросить repaint в UI-потоке.
6. Запустить/перезапустить односекундный JUCE timer.
7. После timeout восстановить подпись активной вкладки и repaint.

Альтернативная точка — callback `SetupRotaryAutoFocus` `0x01654180`, но сначала
нужна динамическая трассировка. Статический анализ доказывает, что он назначает
фокус при булевом событии, однако пока не доказывает, что событие является
именно нажатием `cursorCentre`. Патчить его до трассировки рискованно: значение
может показываться только при вращении K или, наоборот, не показываться при
нажатии энкодера.

Не рекомендуется патчить общий `ADA2CursorResponder`: он используется другими
режимами, где энкодер уже имеет другую семантику, включая Seq и Step Edit.

## Что менять не нужно

- направление обхода K1/K2/K3;
- распознавание и приоритет `Shift`;
- обработчики вращения K1/K2/K3;
- значения параметров и их диапазоны;
- DSP, resampling, sequencer и pad lighting;
- сохранение проекта и совместимость файлов;
- три обработчика вкладок Sample `0x016672c0..0x016675cc`;
- ядро Linux, драйверы кнопок, MCU и загрузчик.

## Где физически лежит изменение

Минимально изменяемый системный файл — только:

```text
/usr/bin/MPC Sample
```

Он находится в третьем ext4-разделе образа. При постоянной упаковке пришлось бы:

1. заменить ELF в `part3.ext4`, сохранив путь, права, владельца и SELinux/xattr,
   если они присутствуют;
2. пересобрать ext4 без изменения ожидаемого размера раздела;
3. XZ-сжать компонент `part3` теми же параметрами;
4. обновить смещение/размер компонента и его SHA-256 в заголовке `AZ0x`;
5. пересчитать все последующие смещения, если размер сжатого компонента изменился;
6. заново подписать заголовок официальным закрытым ключом Akai.

Последний пункт сейчас блокирует штатную установку: `update.img` содержит
RSA-2048 PKCS#1 v1.5 подпись в `0x198..0x297`, а подписанный SHA-256 относится к
`update.img[0:0x190]`. В этой области находятся хэши компонентов. Открытого
ключа `akai-1.pub` достаточно только для проверки, не для создания новой
подписи.

Исходные контрольные суммы:

- `part3.ext4`: `3E03524E7165585BCFF90E40CAB54B6B413678F51D6646D4A305B6C0D3C85C25`;
- `update.img`: `5C49811B80B75C246B203896A581AECDCD6DD813DB6F28F9D1F2183BA85D8C99`.

## Безопасный способ разработки

Прошивка содержит включённый `testapp`-launcher, который останавливает сервис
`ac50`; штатный сервис запускает приложение через `/usr/bin/launch-ac50`, а тот
выполняет `/usr/bin/MPC Sample`. Это позволяет сначала проверять изменение как
непостоянный unsigned test app или как загружаемый hook рядом со штатным
процессом. После перезагрузки устройство возвращается к подписанной системе.

Перед любым постоянным изменением нужны:

1. лог события `cursorCentre`, старого/нового focus и адреса активного
   `ValueLabel` на реальном устройстве;
2. тест всех Sample-вкладок и всех текстовых/числовых типов значений;
3. проверка повторного запуска таймера при быстрых нажатиях;
4. проверка выхода из экрана до timeout;
5. подтверждённая процедура восстановления устройства;
6. отдельное решение проблемы подписи — штатный `update.img` сейчас не является
   пригодным каналом для модифицированного payload.

## Что ещё не установлено точно

- точные смещения трёх текущих `ValueLabel` внутри объекта `SampleModeScreen`;
- получает ли `SetupRotaryAutoFocus` событие от `cursorCentre`, от вращения K
  либо от обоих источников;
- есть ли готовый общий компонент кратковременного сообщения, который можно
  переиспользовать вместо добавления состояния;
- принимает ли загрузчик устройства модифицированный образ при каком-либо
  сервисном режиме;
- можно ли безопасно использовать `LD_PRELOAD` в testapp-контексте или удобнее
  запускать отдельную пропатченную копию ELF.

Эти пункты требуют динамической трассировки на настоящем устройстве. Они не
мешают определить архитектуру изменения, но мешают честно выдать готовый
байтовый патч и тем более безопасный прошиваемый образ.
