# Замечания Leusha и очередь проверок

Актуальная сводка на **3 ноября 2026**: подготовленный предварительный **r27e**,
публичный **r26s**. [Статусы](KNOWN_ISSUES.ru.md) · [Полные изменения](RELEASE_NOTES-r27e.ru.md) ·
[Готовность](RELEASE_READINESS-r27e.ru.md). Исходные номера и формулировки ниже
сохранены. Упоминания Mod Off описывают историю: в r27e проверять обычное
выключение и запуск stock без карты. Реализация не закрывает весь аппаратный случай.

## Результат расследования r26k (локально)

Воспроизведена отдельная ошибка порядка старта: прежняя автозагрузка могла
запускаться при открытом штатном диалоге недостающих сэмплов/ошибки, который
разрешает события на других компонентах. После отмены незавершённой загрузки
оставался пустой проект, хотя мод уже считал восстановление выполненным.
Кандидат r26k ждёт закрытия всех штатных модальных окон и заново отсчитывает
2,5 секунды. Прежний код воспроизводит проблему в ARM-тесте, исправление проходит
normal/UBSan; в полной VM проверено ожидание обоих диалогов и последующая загрузка B.

В тесте Mod Off копия B сохранила ноты 0/960/1920, темп 137, микшер 0,25 и
доступный сэмпл. После выхода stock вернулся к A с темпом 103. Недостающие сэмплы
в выходной копии не обнаружены. Это не закрывает все варианты L01–L03 Leusha:
его точная последовательность и версия по-прежнему нужны при повторе ошибки.
В r26y добавлены метаданные исходного имени/папки и подтверждение первого Save
после восстановления (L04). Аппаратный проход остаётся обязательным. [Подробности r26k](RELEASE_NOTES-r26k.ru.md).

область расследования, но не подтверждает автоматическое восстановление и Mod Off.

### Матрица для №1–4

Использовать отдельные тестовые копии A/B с различимыми сэмплами, нотами,
секвенциями, темпом, mute-состояниями, микшером/FX и Pad Colour.

1. Stock A → запуск мода → автоматический B.
2. Пустой stock A → запуск мода → автоматический B.
3. B в моде → изменение без ручного сохранения → Mod Off → stock → перезапуск.
4. B в моде → ручной Save → Mod Off → открыть другой проект в stock → перезапуск.
5. После каждого перехода проверить обычный Save: отображаемое имя, фактический
   путь записи и сохранность исходных A/B. Отдельно проверить выходную копию.

Для автозагрузки записать пути и время изменения XPJ: текущий механизм выбирает
самый свежий сохранённый файл в Projects или на один уровень ниже, а не последний
вручную открытый проект. Нельзя смешивать ошибку выбора проекта с частичным
открытием правильно выбранного XPJ.

Критерий прохождения: загружен ожидаемый проект целиком, его сэмплы разрешаются,
ошибок открытия нет, обычный Save имеет понятное назначение, исходники сохранны.
При повторе ошибки сохранить журнал через Mod Off и записать точную версию,
порядок действий и имя/путь файла, которого касается сообщение.
