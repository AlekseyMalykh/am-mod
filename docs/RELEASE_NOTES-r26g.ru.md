# Кандидат r26g — Scaled/Pickup Takeover

[English](RELEASE_NOTES-r26g.md) · Работа по [обращению #2](https://github.com/AlekseyMalykh/am-mod/issues/2), заменяет r26f.

В Scaled быстрый поворот ручки мог не доводить параметр до края. Очередь r26f объединяла всё движение до последней позиции. Штатный Scaled использует первое положение для инициализации истории; если получить только крайнее положение, параметр может не измениться. Для Pickup важны также смены направления, чтобы распознать пересечение сохранённого значения.

r26g сохраняет начальное положение каждой ручки, точки смены направления и последнее положение. Объединяются только промежуточные точки однонаправленного движения. Кнопки/пэды/энкодер и смена владельца управления остаются границами; итоговый фокус соответствует порядку движений. Настройка takeover и штатный алгоритм не меняются. Исправление относится к разным страницам параметров, включая Warp.

## Проверки

- Выполнен настоящий обработчик takeover из прошивки (`0x15f5690`): прямое движение Scaled давало 0, через очередь r26f оставалось 0,45. Исправленная очередь совпадает с прямой штатной обработкой в Scaled, Pickup и Jump: оба края, движения с разворотами, события всех трёх ручек и пять начальных значений параметра.
- Пройдены ARM/QEMU и UBSan-регрессии ввода: полная/циклическая очередь, границы действий/владельцев, 50 000 конкурентных обновлений, ввод имён и ресэмплинг. Загрузочный конструктор устанавливает все 50 перехватчиков.
- Получатели GUI/параметров/таймеров заменены тестовыми заглушками; расчёты takeover выполняет штатный код прошивки. Физические потенциометры, полный экран Warp и аудио не проверялись. Нужна проверка на устройстве.

Прошивка **1.3.0.12**, exFAT и **экспериментальный FAT32**, как в r26e. Заменить полную папку `autorun/` либо использовать установщик 1.0.2. Переформатировать карту или переносить проекты/сэмплы не нужно. Кандидат не опубликован.
